# 读前必看（主设计负责人注）

1. **代码 key 以 `src/core/ju-data.js` 为准**：参加者 stage = `pending / invited / invited_queue / waitlist / gathering / tear / contact / going / reschedule / ended / cancelled / rejected / withdrawn / exited / declined / expired / released / queue_left`（本清单里的 `reservation_released` = 代码里的 `released`）。`ended_other` 与 `confirmed_fallback` 不在演示数据里，不要求实现。局主行由 `JU.derive.hosted()` 给出 `section`（todo / resched / recruit / formed / ended / cancelled）、`label`、`status`、`life`、`cta`、`seats`。
2. **§0 的「物件映射」与 §H 的 F01–F11 参数是旧原型的记录，不是本轮基线**：局卡 / 票根 / 票墙卡 / 书脊的形态、时长、曲线全部由各方案自行设计。本轮必须覆盖的 11 个动效族是客户简报的清单（下表），每族在每个方案里都要有开始 → 过程 → 落点：

| 族 | 简报要求 | 必须出现之处 |
|---|---|---|
| M1 | 参加者 / 局主身份切换 | 顶部身份切换 |
| M2 | 当前 / 草稿 / 历史与必要筛选切换 | 分区切换 |
| M3 | 滚动及顶部层级变化（采用标题收起时完整设计连续过程） | 当前较多 / 历史较多 / 管理页滚动 |
| M4 | 局卡与票件展开成详情、关闭并回到来源 | 所有 `p_detail` / `p_ticket` / `p_history` / H1 进入与返回 |
| M5 | 审核、邀请、谢绝与待处理计数、席位的变化 | C2 → 列表计数与座位 |
| M6 | 弹层、抽屉或局内面板的进入、切换、关闭 | 确认层、改时间、取消、散场、局卡、联系层 |
| M7 | 改期、回应、旧票到新票及其列表落点 | `p_answer_time` 接受 / 拒绝；C7 提交 |
| M8 | 出票 / 打印、撕票、联系信息展开、作废 / 燃烧 | `tear` 首次打开、`p_ticket`、`contact`、C9 取消、`p_exit` |
| M9 | 记为散场、出席印记、记录更正与历史归档 | C10、C11、历史分区 |
| M10 | 草稿删除、相邻内容让位、撤销恢复 | 草稿分区 |
| M11 | 从有内容到空态或结果态的完整变化 | 最后一项处理完、取消后、`ds_empty` |

3. 文案以 `JU.COPY` / `JU.RULES` / `JU.STAGE` / `JU.GROUPS` 为准（与本清单一致），数字口径以 `JU.derive` 为准。
4. 「惰性」入口（继续编辑草稿 / 再开一局 / 去找局 / 去开局 / 查看进度 / 账户级记录页）= 保留文字与位置、不可点、不跳转；可用禁用态或说明文字表达。

# 我的局 · 共同视觉状态清单（state-inventory v1）

十个设计概念共用的一份清单：每个概念都必须把这里的每个状态、每个表面、每个动作做出来，用同一套 ascii key。

## 0. 约定

| 项 | 规则 |
|---|---|
| key | 全部 ascii，代码直接用：参加者 `pending…ended_other`，局主 `host_*`，草稿 `draft_*`，表面 `h1_*`，动作 `p_*`，数据集 `ds_*`，动效族 `F01–F11` |
| 列表分组意图（我参加的） | `act` 需要我回应 → `soon` 即将赴约 → `wait` 仍在等待（当前分区，固定顺序，空组不渲染）；`hist_kept` 散场 / `hist_closed` 未成行（历史分区） |
| 列表分组意图（我发起的） | `todo` 待你处理 → `resched` 改期中 → `recruit` 招募中 → `formed` 已成局；草稿分区 `drafts`；历史 `hist_ended` 已散场 / `hist_cancelled` 已取消 |
| 徽标 | 我参加的 = `act` 行数（aria `N 项要你回应`）；我发起的 = `todo` 行数（`N 项待你处理`）；0 不显示 |

| Lead 项 | 参加 = `act[0] ‖ soon[0]`；发起 = `todo[0]`。只有 lead 有实体 CTA 按钮、一句说明、6h 进度条（有 deadline 时）；其余行只有行内入口文字 `动词 + 名词 ›` |
| 排序 | `act`：deadline 升序（无 deadline 排后）→ 权重 invited 0 / reschedule 1 / tear 2 / contact 3 → 活动时间；`soon` / `wait`：活动时间升序；`hist_kept`：endedAt 降序；`hist_closed`：活动时间降序；`todo`：审核意图先于出席，再按活动时间；其余局主组：活动时间升序 |
| 文字四角色 | 每个事项固定顺序：局名 → 时间·地点 → 状态（色点 + 13px）→ 动作。状态永远写在文字栏，不贴在物件上 |

## C. 管理这局（H1）12 个表面

通用：标题永远是**局名**（折叠后单行省略）；meta = `{status} · {when}`；所有写入失败在**发生处**原位出 alert（`{适配器消息}` 或 `这一步没有生效，请刷新后重试。`），成功不出横幅、不出 toast（例外：改时间、复制）。头部 status 优先级：`已取消` → `N 人出席未记录` → `已散场` → `N 份申请待审` → `N 人未答复新时间` → `已成局` → `N 人已预留 · 等确认` → `招募中`。

## G. 语义保留规则（设计最容易写错的地方）

1. **没有公开信用分**。任何地方不出现评分、等级、`极好 / 良好`、星级或「信用 N 分」；只陈述事实（`不占主动退出机会` / `待核实 · 未处罚`）。
2. **八种「没去成」是八个不同事实**：`cancelled`（局主取消）· `rejected`（审核未通过）· `withdrawn`（撤回申请）· `exited`（主动退出）· `declined`（拒绝改期）· `expired`（预留到期）· `reservation_released`（放弃未确认预留）· `queue_left`（退出候补），各有自己的状态词与副文，不合并为「已退出」一种。
3. **`未出席` ≠ 缺席处罚**：出席是局主记录的待核实事实，可随时更正并留痕；`待定` 是主动选择，`未记录` 是没有选择；任何地方不写「扣分」「处罚」「拉黑」。
4. **不发明惩罚**：唯一存在的规则是「主动退出占年度 4 次机会」（只对 `exited`）。放弃预留、到期、退候补、拒绝改期、局主取消都明确写「不占 / 不记」。
5. **规则缺失处用中性事实**：`ended_other` 写 `散场 · 你不在确认名单`；`gathering` 不加退出入口；8 小时联系窗不加倒计时、不加逾期后果。
6. **局主侧数据不给参加者**：申请人留言 / 邮箱验证 / 微信、其他成员的微信与 `已自报加微信`、离开记录、候补名单真名（参加者只见 `X**`）、出席轨迹，只在 H1。参加者只在撕开有效票后看到**局主**微信。
7. **成局是不可逆事实**：`establishedAt` 写入后，他人退出 / 拒绝改期不使局解散、不使我的有效票失效；`已成局 · 已出票` 的局仍可有空位。
8. **票的三种不可用各写各的**：改期待答复（旧票持有不可用、新票待撕）· 取消（作废、烧毁）· 退出（作废、烧毁、联系关闭）；撕票语言只在出票后出现（出票前写 `等成局出票`）。
9. **计数口径写在数字旁**：`已确认 2/5（含你）` / `4/5 已确认（含局主）` / `已答复 2/3`（含拒绝者）/ `n/N 人到场`（`待定` 不计入 n）；容量含局主。
10. **一个时间格式**：`WD MM.DD · HH:MM`；改期时新时间只出现一次，旧时间只出现在一处（票根删除线或 `原定`）；弹层写 `纽约时间`。
11. **`已加微信` 只是自报**：不代表对方回复或到场；散场 24 小时后双方联系入口都关闭。
12. **结果出现在动作发生处**：审核结果原位替换按钮、撤销在删除之前、历史不重放盖章；只有删除草稿、复制、改期已发出才用 toast。
