## 2. 三个核心动作

### ① 状态翻牌（M5 / M7 / M1 / M2 的落定方式）
- **触发**：任何翻牌键下的文字改变（`cells(key, text)` 在渲染时比较上一次文字）：审核通过 / 谢绝后管理盘头部状态「2 份申请待审 → 1 份申请待审」、出席记录「未记录 → 出席」、取消后「已取消」、参加者侧「待撕票 → 待联系 → 待赴约」、牌头标题「局主改了时间 → 新时间已确认」、列表行状态与时间（改期接受后时间格翻到新时间）。身份 / 分区切换用整板翻（见下）。
- **运动对象**：每格四层（`.c02-fh.top` 新面上半、`.c02-fh.bot` 旧面下半静止；`.fa` 旧面上半、`.fb` 新面下半旋转）。文字本身不位移，只有翻片在翻（REF33 的「只有边在走」）。
- **分段**（每格）：fa `rotateX(0→-90deg)` 170ms `cubic-bezier(.55,0,.9,.6)` 轴在格底；fb `rotateX(90→0deg)` 210ms `cubic-bezier(.2,.8,.3,1)` 轴在格顶，延迟 160ms；落定「咔」`translateY(1.5px)` 140ms 在 +340ms；格间错峰 55ms × 格序号（`--i`）。变换中心：fa `50% 100%`，fb `50% 0`；每格 `perspective:260px`；`backface-visibility:hidden`。
- **结束**：flip 类在 `60ms × 字数 + 620ms` 后移除（`forceUpdate`），各层回到静止（旧面 = 新面），文字清晰无残影（实际观察：`evidence/C02/manage/`、`end-att/` 中翻到一半与翻完的帧）。
- **整板翻（身份 / 分区）**：身份牌先 150ms 滑动并按覆盖像素反色（`.c02-plfg` `clip-path: inset(0 50% 0 0) ↔ inset(0 0 0 50%)`，REF15），同时所有行 `rotateX(0→-90deg)` 220ms（机械曲线，错峰 `min(i,9)×22ms`）→ 300ms 后换身份、滚动归零 → 行 `rotateX(90→0)` 320ms `cubic-bezier(.2,.8,.3,1)` 同样错峰；分区切换同构（240ms 换）。`perspective:1000px` 在 `.c02-list`。
- **中断 / 重播**：翻牌过程中切换数据只会让新文字再翻一次；`board` 忙时忽略再次切换；评审「重播」在 `beforeReplay('flap')` 里把最近翻过的键恢复成旧文字再翻一次；`.rm` 下 1ms 直接换面。

### ② 过闸撕票（M8 撕票 + 出票）
- **出票（打印的站牌版）**：触发 = 本版票第一次打开（`tear` 行的票面、改期新票、确认入局后 `formed`）。卡从读卡槽上方的出卡区**向上**分段露出：`c02-issue` 2200ms linear，`translateY 104%→70%`（0–18%）停（18–26%）`→30%`（26–48%）停（48–56%）`→-2%`（56–80%）`→1%`（88%）`→0`（100%）。**卡身始终不透明、轮廓完整**；只有字迹被揭示：卡面内一层与卡面同材质的空白塑料盖层 `.c02-ink`（z 1，盖住字迹、不盖磁条与琥珀线带），其 `mask: linear-gradient(180deg, transparent var(--c02-ink), #000 calc(var(--c02-ink) + 7%))` 由 `c02-inkdown`（同 2200ms linear）推进：`--c02-ink` -8% → 15%（18%）→ 30%（26%）→ 57%（48%）→ 70%（56%）→ 90%（80%）→ 104%（88%）→ 110%，即**自上而下**、走纸段落后槽口约 12–14% 卡高、停顿段追平——看得到「露出—停顿时印上字—再露出」。改期新票的 `时间已改` 章在走纸末段（+1640ms）才盖下（`c02-stamp` 520ms）。读卡灯琥珀、显示屏「出票中 · ISSUING」；出票中卡 `pointer-events:none`，提示「打印完成前不能插卡」。`.scrub` 下卡与盖层同时 `animation-play-state:paused` + `animation-delay:-frame×dur×k`；`.rm` 1ms。已出过的版本记在 `tk.printed`，再进不重印。实际观察：`evidence/C02/print/`、`fix-1/m8-print-opaque-card.png`、`fix-1/m8-print-scrub-22-40-52-70-85.png`、`confirm-flow/`。
- **过闸（撕票）触发**：在 `.c02-gatecard`（ready 态，`cursor:grab`）按下并**向下**拖（`setPointerCapture`）；`p = clamp(dy / 150)`；卡 `translateY(p × 58%)` 跟手（无过渡）；显示屏「插入中 · NN%」，提示「再推一点 / 松手 · 读卡」。
- **释放**：`p < 0.55` → `spring` 240ms `cubic-bezier(.2,1.1,.3,1)` 回弹到 0；`p ≥ 0.55` → **先写入** `engine.tearTicket`（改期新票 = `engine.acceptReschedule`），失败则回弹 + 红灯故障条「…请重新插卡」+ 重试（重试直接再吞卡），成功才进入序列。
- **序列**（`gateSeq`，均用 `this.after`，总长 `GATE_DONE` 2720ms）：
  - 0 吞卡 `motor` 260ms 机械曲线到 58%（FEEDING）→ 300 读卡（READING，「请勿拔卡」；磁条此时在槽内）。
  - 900 **对位**：卡被马达推回到 30%（`align` 300ms `var(--ease)`），停在槽口——卡面上 3/4 可见（顶带、时间、局名、地点）；打孔头 `.c02-punch`（钢制冲头 30px + 12px 摆臂，从闸柱一侧滑入，`translateX(96px)→0` 240ms，`.in` 带 140ms 延迟让卡先停稳）悬在过闸靶环上方，冲头 `scale(1.12)` + 12px 投影 = 抬起；显示屏「对位 · ALIGN」，提示「卡停在槽口 · 打孔头就位」。
  - 1340 **打孔**：冲头 `scale(.93)` + 投影收到 2px（90ms `cubic-bezier(.6,0,1,.6)`）= 压下；同帧卡加 `punched punching`：撕裂孔 + 压痕槽 + 应力发白环出现，卡面 `c02-thunk` 170ms 下沉 2px，读卡器 `c02-shake` 120ms，`已过闸 PASSED` 压印 240ms 逐格印出；绿灯「咔 · 打孔 PUNCH」。
  - 1500 冲头抬起（投影回到 12px）→ 1640 摆臂滑出。
  - 副券圆片 `.c02-flychad`（21px、带被打下来的虚线靶环；z 3，**在冲头之下、卡与读卡器之上**）从打孔瞬间起就坐在新孔里被冲头盖住，延迟 390ms（摆臂离开孔位后）才动：`c02-chadfly` 600ms——0–14% 弹出 `translate(3px,-10px) rotate(60deg) scale(1.05)`（`cubic-bezier(.2,.7,.4,1)`），14–88% 带重量下落 `→translate(6px,140px) rotate(380deg) scale(.82)`（`cubic-bezier(.5,0,.95,.6)`），88–100% 进入集屑窗并淡出；集屑窗内圆片 `rest`（`translateY(-22px)→0 rotate(20deg)` 300ms `cubic-bezier(.4,0,.6,1.4)`，`.late` 延迟 900ms）接住它。
  - 2240 吐卡 `eject` 460ms `cubic-bezier(.3,0,.2,1)` 回到 0（PASSED）→ 2720 落定：联系条 `translateY(14px)→0` + 透明度 300ms（局主 · 微信号 · 复制 · 已加微信）。
  - 留下的卡 = 右上角带撕裂孔 + `已过闸 PASSED` 压印的同一张卡，对应「已撕票待联系」，一眼可辨；列表行状态翻成「待联系」。同一时刻只有一个主动作（卡停 → 冲头 → 圆片落 → 吐卡）。
- **变换中心**：卡 `transform-origin: 50% 100%`（槽口一侧）。冲头、圆片的位置都按卡居中计算（`left: calc(50% + 118px / 122.5px)`），360 / 430 宽下仍对准孔位（`fix-1/widths-360-430-tear.png`）。
- **中断 / 重播**：拖动中换数据集会重置；`beforeReplay('gate')` 把卡放回 ready、清空集屑窗、收起联系条，再跑一次序列（不重复写入）。实际观察：`evidence/C02/tear/`（含未过阈值回弹）、`punch-close/`（0.5×）、`fix-1/M4-*.png`（冲头压下、圆片坐孔 / 弹出 / 下落、撕口放大）、`resched-accept/`。

### ③ 过热作废（M8 作废 / 燃烧）
- **触发**：局主「取消这局」→ 确认 → 700ms 处理中 → `engine.cancel` → 面板收起 380ms 后，**局卡条上的小卡飞进读卡槽并长成要烧的那张卡**：先渲染「取消中」区块（卡 `visibility:hidden` 量位）→ 30ms 后量出小卡与大卡的矩形，大卡外包 `.c02-flywrap` 以 `translate + scale(96/318)`（`transform-origin:0 0`）放回小卡位置、局卡条小卡同时变成空槽（深色凹槽 + 虚线）→ 40ms 后过渡到 `none` 560ms `cubic-bezier(.25,.8,.3,1)`（飞行时 `.c02-well` 临时 `overflow:visible`，卡底被读卡器盖住 = 插进槽口）→ 640ms 后在槽口（`translateY(10%)`）开始过热。局卡条在燃烧结束后标「卡已作废」（空槽 + 红字），`formedLine`「已取消 · 不能撤销，票根作废、联系关闭」；从索引进入「已取消的局」时不滚过局卡条与残卡（只闪亮成员区）。同一物件全程只出现一份；`.rm` 下跳过飞行直接烧到残骸。参加者「去不了了」确认退出 / 「新时间去不了」确认 → `engine.exitEvent` / `declineReschedule` → 票面切到作废场景（从票面 / 答复页来：卡已在读卡器里，`burning` 带 260ms 机械过渡被拉进槽口；从成员视图来：作废场景先按行翻入，卡 `inserting` 520ms（延迟 420ms）从读卡器上方落进槽口、显示屏「读卡 · READING」，1000ms 后才点火——同一时刻一个主动作）（**原地烧同一张卡**：拒绝改期时烧的是刚才看到的 `V2 · No. 5101 · 时间已改` 新票，编号、版本、章全保留；旧票不移除，缩小置灰为 `旧票 · 不恢复` 残留；历史里 `新票 · 作废` 下也是这张 V2 卡；只有真的过过闸的卡才带孔）；历史里「局主取消」首次打开烧一次（`burned[id]` 记忆；动画打开时卡先以 `preburn` 停在读卡器里，等详情各行翻入完成后 +640ms 再点火，索引跳转则立即点火），之后静态残骸；`j-d-exited` / `j-d-declined` 直接显示残骸。
