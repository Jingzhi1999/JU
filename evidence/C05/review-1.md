# C05 缝线 · 视觉 / 动效评审 · 第 1 轮

- 评审对象：`concepts/src/C05.dc.html`（HEAD 54c1c5c 工作区），私有构建 `.build/review-C05.html`
- 方法：`tools/coverage.cjs`（50/50 状态，errors 0）+ `tools/capture.cjs` 21 组操作流 + Playwright 探针（时序 / 状态读取）。全部帧、sheet、log.json 在 `evidence/C05/review-1/<flow>/`；22 个 log.json 的 errors 全部为空。

## 通过的项目（有证据）

- 第一眼：lead 裁片是明确主角（42px Cormorant 时间 + 24px 宋体局名 + 红粉笔倒计时 + 基线进度 + 靛蓝织带 CTA），页面标题 / 活动主体 / 下一步三层主次清楚；其余行只有白标 + 时间列 + 局名 + 行内「动词 ›」（coverage/j-home、h-home）。
- 一套系统：参加 / 发起共用裁片 + 白标 + 粉笔组头 + 布边底栏；票件是吊牌、名单是针脚 + 记号表、管理是订单簿账本、弹层是翻起的布角，形态与职责不同。
- 出票：吊牌从右侧布边底下分段抽出、可见停顿，之后棉线描出并打结，挂牌中没有可操作按钮，完成后落定在粉线叉下（ticket f02–f13，confirm f09–f17）。
- 撕票：拖拽跟手、拉 14px 释放回弹（ticket f20–f26），过阈值后写入先于落袋（f36 “线绷紧了 · 正在记录”），线头回弹、吊牌带旋转落进存根袋并仍可读（f37–f40），留下的状态与“待联系 / 已撕”一致。
- 燃烧：同一张吊牌 / 裁片从角点起洞、棕色焦边推进、灰烬散落，落到灰线轮廓 + 作废章，列表进入未成行组并带切角焦痕（exit、resched-decline、cancel、history）；局主取消的参加者首次打开烧一次，再开为静态（history f04–f12 / f24–f26）。
- 结果与返回：撤回 / 退出 / 拒绝改期 / 审核 / 改期 / 散场 / 取消都有原位结果，返回时若换组会先切到新分区再落到原行并高亮（withdraw f16、approve-reject f25、resched-sheet f18、end-attend f31、cancel f36）。
- 计数：发出邀请后 待审 2→1、预留 1→2、空 2→1、针脚加一针、头部状态重算；谢绝后 待审 →0、组头“已处理 2”（approve-reject f11–f19）；改期后 `已答复 0/4`、列表进 `改期中`（resched-sheet f08–f18）；出席 `3/4 已记录 · 出席 2 · 未出席 0 · 待定 1` + 更正轨迹（end-attend f19–f24）。
- 语义：无信用分；八种未成行各有状态词与副文（variants f21–f22）；候补他人 `L**`；参加者只在撕票后看到局主微信；`gathering` 无退出入口；`未出席 · 待核实` 写明不处罚可更正。
- 面板：索引 50/50、1× / 0.5×、关键帧滑杆可双向拖（scrub f07–f12）、重播（beforeReplay 复原整张吊牌再烧，scrub f20–f26）、重置、变体、下一次保存失败均可用；减少动态下打开 / 撕 / 烧 / 取消直接到结果态（rm）。
- 差异：与其余九套在构图（工作台裁片）、字体（细宋 + Cormorant + 粉笔手写）、组件（裁片 / 吊牌 / 订单簿）、材质（坯布 / 棉线 / 粉笔）、过渡（沿折线翻开）五维都不同。

## 缺陷

严重度：**blocker** 无 · **major** 7 · **minor** 14。

### Major

**M1 · 折叠头部：标题压在品牌行上；跳转 / 重置后展开的头部压在已滚动的内容上** — variants f12、f19、f22，homes f03–f05、f16–f19：滚动超过 48px 后 20px 的“我的局”移到 `top:16px`，正好压在 `top:18px` 的“JU 裁缝台 · 周三 12.17”上，两行字叠成一团（CSS 里 `.c05-brand` 没有 compact 规则）。variants f16：从 b-long 跳到 b-long-h 后列表的 scrollTop 被保留而 `compact=false`，长局名“…开门请多包涵 · 来的人都…”从「当前 / 草稿 / 历史」那一行底下透出（头部背景 82% 之后是透明渐变）。这是最常见的列表状态，客户会直接看到文字重叠。
修法：compact 时 `.c05-brand` 淡出上移（或让折叠标题取代 brand 行的位置）；头部实色延伸到分区行下沿 +6px 再羽化 10px；`jumpTo / reset / loadVariant` 后把 `tableRef.scrollTop` 归零并同步 `compact`（或在更新后按实际 scrollTop 计算）。

**M2 · 快速连点：新层被吞、确认层闪退、成功后又出假失败条** — stress f04→f05：点返回后约 120ms 点另一行，Livehouse 详情已经开到 `phase:'in'`，约 600ms 后被上一次 `closeOver` 的 `after(620)` 卸回列表（探针：t+300 detail/in，t+1000 view=list）。stress f16–f19：「继续赴约」后 150ms 内再点「去不了了」，确认层出现后被 `closeSlip` 的 `after(380)` 清掉，接着的「确认退出」点击落空。stress f15：连点三下「发出邀请」，结果行已是“已发出邀请 · 等对方确认”，底部同时出现红线条“没保存上 · 这份申请已经处理过。”+ 重试——成功的操作被报告为失败。
修法：`closeOver / closeSlip` 的延时卸载带序号令牌，只在仍处于 out 时卸载；`openOver / openSlip` 时取消挂起的卸载；`act()` 在 `state.busy` 时直接返回，按钮按 `busy.key` 加 `disabled`。

**M3 · 燃烧落点断档：物件先完全消失、空槽停留，再淡入另画的灰线轮廓，结果卡插入把轮廓推下** — scrub f09–f11：关键帧 50% 时吊牌已基本烧完，50–100% 只有空槽和灰点。exit f19–f22（0.5×）：吊牌已无，只剩一截棉线挂在粉线叉上约 3 帧 → f23 灰线轮廓与“已退出这局”结果卡同帧出现，吊牌区整体下移。resched-decline f10–f11 → f12 同理；history f10–f11 只剩悬空棉线 → f12 棉线也直接消失；cancel f19–f20 裁片头部整块空白 → f21–f22 虚线轮廓淡入。另外灰点先于焦边出现（exit f11–f12、cancel f08–f10）。§6 要求“剩余形态（灰烬 / 残片 / 焦痕）→ 明确结果”是同一物件的残余，现在是“消失 → 换上一张预先画好的轮廓”。
修法：`fx-hole` 的 reach 设为起火点到最远角的距离 + 毛边余量、曲线改 ease-in-out，让洞在 85–90% 才吃完；轮廓 `.on` 在约 75% 开始交叉淡入，并把最后一段焦边作为静态焦痕留在轮廓上；棉线一起烧（变黑缩成短焦头）而不是消失；结果卡在燃烧前预留高度或放在吊牌下方；焦圈半径 >20px 后才散灰。

**M4 · toast 与失败条压住内容，且出现在规则不允许的位置** — resched-accept f22–f26：“已接受改期 · 按新吊牌的时间见”压在局主微信号和「复制」上；ticket f48–f51：“微信号已复制”“已记录加微信…”压在联系说明上；approve-reject f11–f23、end-attend f05–f12（“已记为散场”压在“未出席是待核实的事实…”中间）、confirm f08–f15（压在成员表上）；fail-retry f22–f24 红线失败条盖住提示与席位标题。清单 C 通用：“成功不出横幅、不出 toast（例外：改时间、复制）”，G12：“只有删除草稿、复制、改期已发出才用 toast”；本方案对发出邀请 / 谢绝 / 记为散场 / 已加微信 / 确认入局 / 记下都弹 toast。失败统一显示在屏幕底部而非发生处，文案一律是引擎通用句（撕票应为“未能保存，请重新撕下副券”）。
修法：删掉多余 toast（结果已在原位）；保留的 toast 放进不与内容重叠的固定槽（覆盖层底部 56px 实色条，或贴在 topbar 下）；失败改为原位 alert（申请行内、吊牌区下、弹层内）并用清单文案。

**M5 · 出席行：微信号与「复制」挤断，按钮文字竖排“复 / 制”** — end-attend f05–f09（四行全部：“微信 / leon_hp”叠成两行，「复制」按钮宽度不足、两个字上下排）；width360 f07（430 宽下 阿蒋 / Momo 仍断）；账本 28px 横线同时穿过名字与三段按钮。这是局主散场后的主界面，中文排版直接失分。
修法：出席行改两行网格——第一行 头像 · 名字 · 三段选择；第二行 微信号 + 复制，左对齐名字列；`.c05-chalkbtn{white-space:nowrap}`；行高对齐 28px 账本线或行内铺纸色底遮住横线。

**M6 · 管理页 / 详情滚动没有头部层级变化，返回键与局名一起滚走** — variants f17–f18：长标题局主的局名排三行，滚动后局名与「我发起的 · 当前」返回键都滚出屏幕，没有折叠头；variants f14–f15、resched-accept f20–f26：详情滚动后同样没有返回入口。清单 C1“折叠头（局名 30→18px）”、C 通用“标题永远是局名（折叠后单行省略）”、M3 族“管理页滚动”都要求。
修法：`.c05-oscroll` 内加 sticky topbar（返回 + 单行省略的局名 + 状态）；裁片头滚过约 88px 时局名从裁片上缩小上移进 topbar，做成连续过程；详情同理。

**M7 · 拒绝改期后，结果写“席位已释放”，下方席位仍是 5/5 且名单写“阿禾（你）已确认”** — resched-decline f12–f22。探针：`declineReschedule` 之后 `counts.confirmed` 仍为 5、seats 仍含你（`exitEvent` 会把你移出，decline 不会）。同一屏两个相反的事实，属于“计数正确”的验收项。
修法：方案侧在离开结果出现后把席位块改为“你已离开 · 席位已释放”并去掉你的那一针；同时请主负责人在 core 的 `declineReschedule` 里把你的成员状态设为 declined，使计数变为 4/5（可能影响其余九套）。

- **m2 · 翻开 / 折回的字号跳变与收回穿帮** — open-back f03：第一帧行内 27px 时间 / 19px 局名直接换成 42 / 24px；f21→f22 落回时反向一帧切换；open-back f20：收回时背景遮罩先撤，半折的下半片文字压在列表页脚文字上。start / out 阶段头部用行的字号（或对内层做反向缩放），遮罩保留到 clip 收拢到行矩形。
- **m3 · 撕票过程文案与布局跳动** — ticket f36：写入中需求行写成“出票中 · 吊牌正在系上”，「去不了了」被移除使名单上跳约 80px；f40→f41：联系卡插入把下面整段下推约 130px，只做了淡入。snapping / falling 时用“线绷紧了 · 正在记录”，行动区保留 disabled 占位，联系卡用高度过渡展开（像从吊牌下翻出的布角）。
