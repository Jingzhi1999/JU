## Major

### M1 · 参加者详情 / 结果页没有局名：局卡上的主角一打开就不见了
- **状态 / 动作**：`p_detail` 的 pending / invited / invited_queue / waitlist / gathering，以及 cancelled / exited / declined 的结果页。头部 26px 大标题是 `detailTitle`（「等待审核」「已预留 · 等你确认」「候补中」「等待全员确认」「局主取消了」……）。局名不在页面任何位置，只有带通行证或局卡缩略的状态里才有。
- **证据**：
  - `probes.json` 的 `event_title_in_detail_pane`：9 个状态里 7 个为 false。
  - `zoom/cov-g1.png`（第 3、4 张）、`zoom/cov-g2.png`（第 1–3 张）、`zoom/cov-g4.png`（第 2 张）、`zoom/cov-g5.png`（第 1 张）。
  - `detail-open-back/f01–f04`：列表板上的「法拉盛早茶 · 周日十点」展开后变成「等待全员确认」。
- **违反**：state-inventory D `p_detail` 必显「局名 · 区 · 街区 · when · 状态」；contract §0「局名与时间地点形成比例差」；同一物件运动前后身份连续。
- **修复**：头部改为「眉注 = STAGE_EN + 状态（已有）→ 大标题 = 局名（22–26px，两行截断）→ 一句 detailTitle 状态句（15px）→ 时间 · 地点」。作废空框里保留一行蚀刻的局名（或局卡缩略）。

### M2 · 作废序列开头先出结果、通行证消失再出现（参加者退出 / 拒绝改期；局主取消同类）
- **状态 / 动作**：`j-d-withdraw → 确认退出`，`j-d-reschedule → 去不了了 → 确认退出`。
  - 弹层收起期间，详情已经换成结果标题「已退出这局 / 未接受新时间」，通行证从页面上消失，正文是空的。
  - 约 460ms（1×）/ 950ms（0.5×）后通行证重新出现，标题倒退回「票根作废中」，才开始碎。
- **证据**：
  - `probes.json` 的 `exit_void_timeline_1x`：434ms 无 pass + 已退出这局 → 898ms pass + 票根作废中；0.5× 是 851 → 1803ms。
  - `zoom/exit-gap-0.5x.png`（`flow-exit/f06–f08`）、`zoom/decline-gap.png`（`flow-resched-decline/f08–f10`）、`flow-decline-half/f08–f10`、`fail-retry-destructive/f10–f11`。
- **局主侧**：`zoom/host-cancel-start.png` 第 1 张（`host-cancel/f10`）。弹层收起后先出现完整的已取消页（头部「已取消」、成员「取消前已确认 票根作废」、离开记录、帮助文案），下一帧胶囊和成员区让位、副本升起，版面跳一次。
- **影响**：结果先于动作；同一张票在作废前消失一次。这和 round-1 M1 是同一类问题，换到了作废链路上。
- **修复**：
  - 引擎写入成功的同一回调里先快照 `fx.pre`（撕票时已经这么做），同步进入 `shatter-rise`，让 pass 和撕前标题在弹层收起期间一直在。结果层与「已退出这局」只在 `void` 落定后出现。
  - 局主侧在副本升起前保持取消前的头部与胶囊，或者先插入副本槽位再改状态文本，避免两次重排。

### M3 · 减少动态把内容计时器一起清零：提示条永远不出现，草稿撤销窗口变成 0
- **状态 / 动作**：面板「减少动态」开启后：
  - 联系层「复制」后提示条「微信号已复制」从未出现。`probes.json` 的 `reduced_motion_copy_toast`：开启时 30 / 120 / 400 / 1500ms 都是 none，关闭时 2.6s 内一直可见。
  - 删除草稿后撤销条不出现、立即提交。`reduced-motion/f30–f33` 中「未命名的局」直接消失，没有撤销条；`probes.json` 的 `undo_bar_present_after_400ms: false`。
- **原因**：core `after()` 在 `rm` 下 `k = 0`，C04 用它来控「10s 撤销窗口」和「2.6s 提示条」。
- **影响**：减少动态用户删除草稿后没有撤销，违反 G12「撤销在删除之前」。改时间等提示也全部丢失。
- **修复**：内容时长（撤销 10s、提示 2.6s、处理中最短停留）不随 rm 缩放，用不缩放的计时器，或在 core 里加 `after(ms, fn, {real:true})`。只有动画段才走 k。

### M4 · 缺「局内记录 · 举报」层
- **状态 / 动作**：`p_history`（ended / 未出席待核实 / 未成行）。规格要求 `不对劲？举报` → 层「说说发生了什么」（≥4 字）+「谁」chips（含「（局主）」）+ 截图 ≤6 → 提交 →「已受理 · 可在“设置 → 帮助与反馈”查询进度。」，失败「提交失败，内容已保留。请重试。」。
- **证据**：C04 源码里「举报 / 说说发生了什么 / 已受理」出现 0 次（`probes.json`）。`zoom/cov-g4.png` 第 1 张与 `coverage/j-d-absent.png` 只有一行「补充一句说明… / 添加」。另外 7 套方案都实现了这一层。
- **修复**：在历史详情的局内记录区加一个厚玻璃底部层，承载这套举报流程（含失败 / 重试与「已受理」结果构图）。现有的「补充说明」可以保留为局内记录的轻量入口。

### M5 · 局主取消后，参加者首次打开没有碎裂（F08-C「首次打开烧一次」缺失）
- **状态 / 动作**：`j-history → 深夜拉面（cancelled）`。展开直接是落定的空框 + VOID，没有从完整通行证开始的碎裂。
- **证据**：`zoom/cancelled-first-open.png`（`flow-history/f14–f18`）。
- **违反**：state-inventory A `cancelled`「首次打开烧一次 F08-C，之后静态」，F 表 s12 行，H 表 F08。参加者从未看到自己的票被作废。
- **修复**：参加者侧给每条 cancelled 记一个 `seenVoid`。首次打开时复用 `shatter-pass` 序列，跳过确认层，从完整通行证开始。之后都是静态空框；`.rm` 下直接是空框。
