# C01 票据卷 · 视觉 / 动效评审 · 第 1 轮

- 评审对象：`concepts/src/C01.dc.html`（工作区 HEAD e92e5e8 + 未提交修改），私有构建 `.build/review-C01.html`
- 方法：`tools/coverage.cjs`（50/50 状态，errors 0）+ `tools/capture.cjs` 20 组操作流，全部帧与 sheet 在 `evidence/C01/review-1/<flow>/`。所有 23 个 log.json 的 errors 均为空（几组曾因评审脚本自身选择器写错而带“click target missing”，已修正并重跑）。
- 结论：**不通过**（blocker 0 · major 7 · minor 11）。核心三动作（走纸打印、沿孔撕票、焦卷作废）都真实存在且分阶段、同一物件、有残余与落定结果，这是本方案最强的部分；不通过的原因集中在：身份切换的纸卷材料逻辑、连点防护、取消态的一致性、中文排版的悬挂分隔号、C12 遮挡、未成行历史的构图完整度、滚动时分区行丢失。

## 通过的项目（有证据）

- 第一眼：大号 mono 时间 + 粗体局名是明确主角，lead 行独有实体按钮 + 进度条；时间 / 地点 / 状态 / 动作四层级分明（coverage/j-home, h-home）。
- 角色：机壳上的两卷拨杆常驻，参加 / 发起共用一套纸卷系统，分区 / 组头 / 行 / 票 / 便签 / 残片形态各异（不是同一种圆角容器）。
- 打印：票从印头分三段露出、停顿可见、印头阴影、打印中副券写“出票中”且不可撕、完成后票面清晰落定（ticket f09/f12/f15/f20）。
- 撕票：从右端受力、渐进断口 + 纤维带、未过阈值回弹（ticket f25）、写入先于落券（f38 标题已变“联系局主”）、存根槽计数（f44）、留下的票底边锯齿与“待联系”一致。
- 燃烧：同一张票 / 活动条从起火点起洞、炭圈 + 余烬推进、纸灰落向底栏、残片 + 结果块（resched-decline f10–f23, exit-burn f09–f17, cancel f05–f15）；参加者 `cancelled` 首次打开显示残片。
- 结果与返回：每条路径都有结果块并返回到来源分区且高亮原行（withdraw f16, exit-burn f27, cancel f27）。
- 计数与语义：审核后 待审 −1 / 预留 +1 / 空 −1 / 座位段补一格 / 头部状态重算 / 徽标重算（approve f12, f22）；改期后列表行进 `改期中`（host-resched f17）；散场后 `N 人出席待记录` 与历史 `n/N 人到场`（end-att f25–f26）；八种未成行各有自己的状态词与副文（history-many）；候补他人显示 `L**`；无信用分；局主侧数据未出现在参加者页。
- 失败 / 重试：三处写入失败都在发生处出红边纸条，重试成功；撕票失败副券复位后重试再落（fail-retry f19–f22）。
- 面板：索引 50/50、0.5×、暂停 / 继续（scrub-check f06–f09）、重播（beforeReplay 复原后再烧，scrub f08–f10）、重置、变体切换、失败按钮均可用。
- 减少动态：打印 / 撕 / 烧 / 切换都直接呈现结果态且可理解（rm）。

## 缺陷

严重度：**blocker** 无 · **major** 7 · **minor** 11。

### Major

**M1 · 身份切换时新纸卷“尾部先出”** — roll-switch f06–f07（0.5×）。当前卷收回出纸口后，另一卷以 `translateY(-780px)→0` 走出，但纸卷比视口长，于是先看见的是新卷的**下半段**（“阳台烧烤 … 本卷到此”页脚），然后内容整体下移，最后才出现回单头与分区行。热敏纸不可能从页脚先出，物件运动与材料逻辑矛盾，且这是每次切换都会看到的 M1 族动效。
修法：让新卷从出纸口**头部先露**：在 `.c01-roll.in` 上用 `clip-path: inset(0 0 100% 0)`→`inset(0)`（或 max-height）与位移同帧推进，等价于打印走纸；或在切换期间把 `.c01-feed` 滚到顶并用出纸口遮罩只露出已走出的长度。

**M2 · 没有连点防护，第二次点击触发引擎错误并弹出“没有保存成功”** — approve f15–f22（谢绝连点两次 → 红条“这份申请已经处理过。”）、stress f13–f14（草稿删除连点 → “草稿已不存在。”；撤销连点 → “没有恢复成功”）。`act()` 不检查 `state.busy`，每次点击都排一个 `after()` 写入；第二次写入必然失败，用户在动作已成功的情况下看到失败条，且该条跨标签页持续存在（approve f25）。同时 `.c01-app` 里的处理中三点只渲染在“发出邀请”里，按“谢绝”时显示的是“发出邀请 ···”（approve f16）。
修法：`act()` 开头 `if (this.state.busy) return;`，并在按钮上加 `disabled`/`pointer-events:none`；三点按 `busy.key` 分别渲染到被按下的那个按钮；`deleteDraft` / `undoDelete` 同理加 `leaving`/`undo` 守卫。

**M3 · 取消后的工单不一致** — coverage/h-m-cancelled：跳转到已取消的局时，进度行“已确认 3/6（含你）· 预留 1 · 空 2”与座位段仍在、局卡缩略仍写“席位已预留”，而下面又同时出现焦炭残片——完整活动条与残片并存；cancel f24 与 h-m-cancelled：已取消后预留成员仍显示**正在走的倒计时**“· 剩 05:02:00”+ 进度条；cancel f12：燃烧结束时局卡缩略的“席位已预留”小标签残留在遮罩外（灰框），然后才被残片覆盖；cancel f27 / coverage/h-history：历史里的焦边条目副文写成“已取消 · 已取消 · 不能撤销…”（chipText 与 need 重复）。
修法：`manageVals` 在 `status==='cancelled'` 时 `burn='burnt', charred=true` 且不渲染 `.c01-strip`；成员行 void 态不输出 `hasCd`；把 `.c01-cardchip` 收进 `.c01-burn` 的遮罩区域（或燃烧开始时隐藏）；char 行副文只用 `need`。

**M4 · 中文排版：悬挂分隔号与孤字** — 每个工单头部的 meta 行“{status} · 周六 12.19 · 20:30 ·⏎Manhattan · 东村”都以“·”结尾再换行（coverage/h-m-review、h-m-members、h-m-attendance、h-m-cancelled、approve f22）；改期对照行“原定 ~~…~~ → 改为⏎周四 12.24 · 20:00”（coverage/h-m-replies、host-resched f08；C7 便签里“→”悬在行尾）；标题折行以“·”起行：“周四 Livehouse⏎· 散场后吃宵夜”（coverage/j-d-reschedule 行副本）、“周六早午餐 · 只聊不卷⏎· 带上一本最近在读的书”（coverage/b-long、scrub f17）；成员行“· 剩 05:02:00”前置孤立“·”（approve f25、cancel f24）；历史页脚最后一行只剩一个“诉”字（coverage/j-d-cancelled、j-d-exited）；工单 90px 局卡缩略里局名被挤成“周五小酒馆试营⏎业”“自然酒小试 · 六⏎款”“看展搭子 · 现代⏎馆”（h-m-review、h-m-members、h-m-attendance）。这是客户验收里“中文标题、状态、时间、地点本身要排得好看”的直接失分。
修法：meta 行改为两行固定结构（状态一行，时间 · 地点一行）或用 `white-space:nowrap` 的 `<span>` 包裹“时间 · 地点”整体；对照行把“改为 + 新时间”作为一个不可断单元并允许整行换行；标题的分隔号用 ` · ` 并包成 `<span style="white-space:nowrap">· 下一词</span>`，或改用全角间隔号与 `word-break:keep-all`；成员行有倒计时时不再输出前导“·”；页脚文案缩短或允许 `text-wrap:balance`；缩略卡加宽到 ≥120px 或只印局名首行 + `text-overflow:ellipsis`。

**M5 · C12「局卡」便签：整张局卡盖住标题** — coverage/h-m-card：`.c01-card.big` 被定位在便签标题“局卡”之上，h2 只露出上半截，局卡的“席位已预留”小标签也压在便签边缘上。这是本方案唯一的硬性文字遮挡。
修法：去掉 `.c01-card.big` 的负 margin / 上移位移，或把标题放在卡片内的印刷眉头；卡片 `margin-top` ≥ 标题行高 + 8px。

**M6 · 未成行历史的展开只有文字，退出 / 拒绝改期没有票件残余；到期行文字误用警示红** — coverage/j-d-exited、j-d-declined、j-d-expired、j-d-released、j-d-withdrawn、j-d-rejected、j-d-queueleft 全是“标题 + 三行 kv + 局内记录”的同一张纸，而 `cancelled` 有焦炭残片（j-d-cancelled），同一族物件不一致；清单 D `p_history` 要求 `exited` / `declined` 展开时有“退出时票快照（含是否已撕）· 灰烬”。退出流程当场看得到残片（exit-burn f17），重新打开就没有了。另外 `joinedRow` 对 `expired` 行先按 `deadline` 算出 `hot` 类再被 `tone==='void'` 覆盖文案，于是“预留到期未确认 · 位置已补给他人”整行红字（coverage/j-d-expired、history f24）。
修法：`detailVals` 的 history 模式对 `exited` / `declined` 渲染静态 `.c01-char`（深棕残片，带“主动退出 · 票根与联系已关闭”/“拒绝改期 · 席位已释放”），对 `expired` 渲染 `00:00:00` 条，其余保持纸质摘要但给一个物件（如打了叉的局卡缩略）；`extraCls` 在 `tone==='void'` 时重置为 `c01-cd`。

**M7 · 滚动后分区行消失** — scroll f01–f04（j-many 滚到 120 / 600 / 1600 / 底部）：回单头、`当前 / 历史` 分区行与组头都随纸带滚走，只剩机壳的身份拨杆常驻；清单 E `ds_many_current` 的验证点是“滚到任意深度仍见分段条 + 分区行”，F02 要求“分段条 + 分区行常驻”。管理页同理，工单标签（申请 / 成员 / 安排）滚走后无法切换（scroll f06）。
修法：把 `.c01-tabs` 做成 `position:sticky; top:0` 贴在出纸口阴影下（纸带穿过印头时标签“印在印头上”也符合材料逻辑），或在 `.c01-slot-shade` 上用同样的反白方块复刻当前分区并在滚过 56px 后淡入；工单的 `.c01-wochips` 同样 sticky。

### Minor

- **m1 · 落券的归宿不可见** — ticket f37–f44：副券 `rotateX 70° + scale .68` 一两帧内就缩成一条线消失（f39–f40），直到 f44 才在底栏出现“存根 1”；“有重量地垂落到归宿”只剩起点和计数。建议减小 rotateX（≤40°）、保留 scale ≥.8，让副券沿可见路径穿过纸面下缘再入槽，或在 `.c01-tray` 里做一个同步的“接住”帧。
- **m2 · 烧尽到残片之间的空白** — resched-decline f19–f20、exit-burn f13–f14、cancel f12：洞吃完整张票后容器仍保持原高，纸面空白约 400ms 才折叠出残片。残片应在洞到 ~85% 时就开始从下方淡入，容器高度同时过渡。
- **m3 · 拒绝改期燃烧时副券文字变成“出票中”** — resched-decline f10–f11：确认退出后新票副券的 `stubText` 因 `busy` 判定写成“出票中 <”。燃烧中应为空或“作废中”。
- **m4 · 打印中按返回出现空白纸面 + 行副本穿过其他行文字** — back-print f02（返回后第一帧整张纸只剩行副本，正文瞬间卸载）、open-back f11 / back-print f03 / cancel f26（行副本滑回时压在列表其他行文字上，形成短暂重影）。建议 `phase:'out'` 时正文随纸面一起淡出而不是先卸载；行副本滑回途中给底层列表加 `opacity .3`。
- **m5 · 返回后列表滚动位置改变** — ticket f55、rm f06：`closeOver` 用 `scrollIntoView({block:'center'})` 把原行居中，原本在顶部的列表被滚到标题被切掉的位置。应记录进入时的 `scrollTop` 并恢复，仅当原行不在视口时才滚动。
- **m6 · 改时间便签的原生输入显示美式格式** — coverage/h-m-reschedule、host-resched f03：“12/23/2026”“07:30 PM”，与“一个时间格式 / 纽约时间 24 小时”不符。可用自绘的日期 / 时间选择或在输入上方印出格式化后的“周四 12.24 · 20:00”作为主显示（已有一行，但原生控件仍最醒目）。
- **m7 · 改期详情里新时间出现三次、旧时间两次** — coverage/j-d-reschedule：行副本“改为 …”、副标题“改为 …”、新票时间；旧票删除线 + 新票“原定 …”。清单 G10 要求各出现一次。建议副标题只写地点，新票不再重复“原定”。
- **m8 · 退出候补多了一层确认** — confirm f20–f21：清单 D `p_waitlist` 写明“退出候补 → 直接写入（无二次确认）”。可改为直接写入 + 回执条。
- **m9 · 历史较多没有月份标题** — coverage/j-history-many、history f21–f24：清单 E `ds_many_history` 要求散场跨月时出现月份标题。
- **m10 · 票面详情没有“参加约定 ›”入口** — coverage/j-d-tear、j-d-contact、j-d-going：清单 A `tear` 要求入口“参加约定 ›”（三类约定），目前只有 invited 的阅读层能看到约定。
- **m11 · §10 评审约定未落实** — 源码里没有任何 `data-act`（评审脚本只能靠类名与顺序定位，本轮脚本因此多次改写）；面板下方另加了“C01 本地演示 · 下一次保存失败”，与面板自带的失败按钮重复（§10：不要再放演示控件）。

## 其他观察（不计入缺陷）

- 拖帧（scrub）恢复后燃烧关键帧从 0 重新开始（scrub f06 / scrub-check f03），残片在 ~3–5s 后才落定（scrub f07 为空白，scrub-check f04 已有残片）；暂停 / 继续则正确。这是面板集成的小瑕疵，建议 `scrubTo(null)` 时保留 `animation-delay` 的负值直到动画结束。
- 身份切换、分区切换、管理标签连点都没有卡住的半开状态（stress f15–f19，open-back f13–f16）。
- 回执小条（toast）从底栏升起时会盖住纸带最后一行（ticket f51），可接受。
