- 评审对象：`concepts/src/C10.dc.html`（HEAD 54c1c5c），私有构建 `.build/review-C10.html`

## 通过的项目（有证据）

- **显影出票**：相纸从显影盘液面下分三段升起，中间两次停顿看得清（ticket f03–f10），影像通过斑块遮罩逐步显出，镊子只在显影中出现；显影中副券不在，没有可误按的操作；落定后的相纸与前态材料一致（ticket f11–f18）。成局后的显影也真的会触发（confirm f06–f13）。
- **剪副券**：裁刀从左端开始，已剪 / 未剪两段可以分清，未过阈值回弹（cut f01–f08）。过阈值后先写入，副券卷曲落进底片袋，计数变成「存根 1」，红灯联系层随后滑入（cut f15–f24）。复制后显示「已复制」，点「已加微信」经「记录中」变成「待赴约」禁用态（cut f29–f31）。剪票失败时副券回弹并出重试条，重试成功（fail-retry f01–f07）。
- **改期**：旧票压暗并带「改期」章，新票显影、带「时间已改」章，「原定」一栏有删除线（resched-accept f02–f06）；剪下新副券后成为待赴约，已加微信沿用（f16–f19）。局主侧确认改时间后，旧时间划掉、新时间重印，toast `已改时间 · 等 4 位成员答复`，出现改期答复 0/4，列表变为改期中（host-resched f13–f23）。同一时间和清空时间时按钮禁用并有提示（f06–f08）。
- **审核**：发出邀请后红蜡笔圈出申请人；谢绝时两笔划叉，结果行在原位落定。计数同帧更新：申请 2→1→0 · 已处理 2，预留 1→2，空 2→1，座位格盖上一格，头部状态和列表行都跟着变（approve f09–f27）。
- **散场与出席**：记为散场后进入处理中，再由出席区接管；0/4→4/4，红蜡笔圈出 / 划掉 / 虚线；「更正」会重新打开三段，并留下轨迹（`更正 出席 → 未出席 · 12.17 15:00`）；列表移到历史的已散场（end-att）。
- **草稿**：删除时该格宽度收起，相邻格补位，出现带引线的撤销条；撤销后回到原槽；10s 后自动提交；在摘要里删除后回到列表并带撤销（drafts）。
- **失败 → 重试**：剪票、已加微信、发出邀请、确认取消、确认退出五处都会显示处理中 → 红灯失败条 → 重试成功（fail-retry）。
- **面板**：0.5×、熔穿进行中拖帧（scrub f02–f08 跟随 10/30/50/70/90/20%）、释放后续播、重播（熔穿与剪副券都能复原再播）、暂停中重播、重置都有效。减少动态下各处直接呈现结果，且看得懂（rm）。
- **历史**：参加者侧取消的局首次打开熔一次，再开时是静态残片（history f02–f12）；散场票根上的出席圈是静态的；补充记录写入轨迹。八种「没去成」的状态词和副文各不相同。
- **身份 / 分区**：两卷胶片横移；分区切换时暗房灯先灭再显影；连点 4 次身份后落在正确的卷（roll-switch f19–f22）。纵向滚动时头部折叠，身份拨片和分区行常驻（scroll f02–f04）。底片条横滚时灯箱扫光，墨色随之反相（strip-hscroll）。
- **边界**：七种空态都是完整构图（未曝光的短片 + 一句话 + 一个动作，惰性动作写明属于哪个模块）；single 不会被拉成详情；long 标题两行、地点省略（drafts-empty）。360 / 430 宽无溢出（widths）。
- **语义**：没有信用分；候补名单是 `L** / 你`，参加者看不到局主侧数据；撤回、拒绝改期、退出、到期、放弃预留、退出候补的副文正确；「未出席 · 待核实」写明不处罚。
- **差异**：横向底片条 / 灯箱 / 相纸 / 底片袋 / 红灯面板 / 红蜡笔、Space Mono + Long Cang、显影 · 剪 · 熔穿，与其余九套至少在构图、材质、组件、核心动作、字体五个维度上不同。

## Blocker

### B1 帧 → 详情 / 管理 / 草稿的展开与收回中途是空白暗矩形（M4 全部入口）
- **现象**：点帧时，源帧（灯箱上奶白发亮的那一帧）先被藏起来（`opening`），`.pane` 以暗房黑底从帧矩形 `clip-path` 扩到全屏。整个过程中 `.body` 的不透明度都是 0（在 160ms × k 之后才用 260ms 淡入），所以中途看到的是一块只有返回栏的空白暗矩形：亮帧先变成暗块，主体帧再淡入。返回时反过来：正文先淡出，暗矩形收缩，列表里源帧的槽位空着若干帧，然后帧才重新出现。背景的退让（scale .965 + brightness .3）几乎看不到，因为暗矩形很快就盖满了。
- **证据**：open-cdp f01–f05（打开），f12–f16（收回）；open-back f01–f04；stress-review f14；构建者的 `evidence/C10/card-detail-back` f01–f03、f10–f13 也是这样。逐帧数据：t=210ms 时 clip 是 `inset(109px 26px 167px 7px)`，`.body` opacity 0；t=444ms 时才到 0.08。
- **违反**：§0「同一物件在运动前后身份连续……不能中途换成另一个素材或空白矩形」；「进入详情时背景要退让……不能只让原卡消失再淡入无关大面板」。方向卡写的是「像相纸显影：先空白再逐渐显出」，但现在的实现是一次普通的不透明度淡入，并没有显影。
- **修复**：让主体帧（`.hero`，和灯箱帧是同一种奶白帧）从 t=0 起就在扩展的 clip 里、处在源帧位置（内层 translateY 已经对齐），只让主体帧以下的正文延迟淡入；想保留「显影」，就对正文用票面那套 `devmask` 斑块显出，不要整块留空。收回时主体帧保持可见，一路缩回源槽位，源帧在 clip 落定的同一帧换回。背景压暗要在 clip 外看得见。

### B2 熔穿把物件整个吃光后换上另画的残片；灯箱侧中途是整块白光（核心动作 ③）
- **现象**：洞的半径 `--reach` 被设成「正好吃尽」（灯箱帧 222px / 票 262px，见 motion/C10.md），烧到 85% 之后物件基本不剩：局主取消时灯箱帧变成整块奶白光（只剩齿孔角），约 0.8s × k；参加者票面变成整块黑。之后 `.rsd` 残片「落定」，但它是一块不同的素材：黑帧框、居中的小椭圆洞、新的标题文字、高度更短。洞反而从全满缩回椭圆，焦边、余下的角、文字碎片都没有留下。
- **证据**：cancel f20–f26（白块）→ f27（残片突然出现）；scrub f06–f07（70% / 90% 时全白）；exit-melt f20–f22（全黑）→ f23；resched-decline f19–f20 → f21；构建者 `evidence/C10/cancel` 同样如此。
- **违反**：§6「燃烧作用在同一张票件上……不是大面积……盖住后直接切掉」；需要有「剩余形态（灰烬 / 残片 / 焦痕）」；验收单「no white flashes」「same object, residue」。
- **修复**：把洞的终点限制在物件的 55–65%（偏心，避开局名首字），让焦环冻结成残片边缘，四角与部分文字留下；残片就是同一物件的终态（同尺寸、同洞形 = 最终 mask，加熔珠），只淡入「VOID · 已熔穿」与说明文字。灯箱侧透过洞的光改为暖暗的琥珀（约 #8a6a3c，不透明度 ≤.6），不要满亮 `#fff9ea`。

## Major

1. **按钮与胶囊的内边距被全局清零**。`.app button{padding:0}`（特异度 0,1,1）盖过了 `.chip` / `.sbtn` / `.cp`（0,1,0）：管理页分区胶囊里的文字贴着边，「申请 2」的计数被边切掉；「谢绝」宽 30px 没有内边距；「复制」宽 23px。实测 chip paddingLeft 为 0px。证据：coverage/h-m-review、h-m-attendance，cut f29，card f01–f08。修复：改成 `.app .chip` 等写法，或把重置写成 `:where(.app button)`。
2. **票面相纸偏右且右缘被裁**。`.melt{position:relative}`（第 377 行）覆盖了 `.tk{position:absolute;left:10px;right:10px}`，于是 .tk 占 26→384，而 tray 只有 16→374：相纸右侧 10px 白边和副券右端被 `traybox overflow:hidden` 裁掉，左右留白不对称（左 26 / 右 6）。证据：coverage/j-d-tear、ticket、cut、resched-accept 的全部票面帧。修复：`.tk.melt{position:absolute}`。
3. **取消后的成员行出现走动的倒计时**。刚取消的局里，Leon 一行写着「取消前已预留 剩 05:02:00」（琥珀色）：一个已作废的预留还在显示剩余时间。而历史里的已取消局（hostpicnic）显示「取消前已预留」，没有倒计时，两处不一致。证据：cancel-after f02（放大图）、scrub 全部帧、构建者 cancel 帧。修复：局已取消时不渲染 `剩` 段，改写「取消前已预留 · 预留作废」。
4. **成局后的显影落在视口外**。从详情底部点确认入局后，`.pbody` 保持原来的 scrollTop：相纸在视口上方升起，落定后只能看到页脚蜡笔和副券（confirm f07–f20）。修复：显影开始前把 pbody 平滑滚到顶（或把显影盘锚定到视口），再开始 `c10-rise`。
5. **接触印样一条只露一帧多一点**。主任务流的提示仍未改：j-many「要你回应 5」只有第 1 帧能读，下一帧的局名只剩两个字（「新手」），条内没有位置指示，要看完要逐条横滑。证据：coverage/j-many，scroll f01，strip-hscroll f00–f09。修复：灯箱帧宽缩到约 78%，露出下一帧的局名 + 帧号，齿孔轨上加「1/5」计数。
6. **申请审核仍是通用列表，按钮抢最强层级**。待处理较多时，6 条整宽琥珀色「发出邀请」纵向堆叠，是页面里最亮的东西，压过灯箱帧和计数（manage-scroll2 f02–f05、coverage/h-m-review）。修复：申请人用接触印样小格（4 列）排开，在格上用红蜡笔圈选 / 划叉；「发出邀请」改成格内次级按钮，或只给当前选中的格一个实体按钮。

## 建议的修复顺序
B1（展开 / 收回的物件连续）→ B2（熔穿留残、去掉白块）→ M1 / M2（两处 CSS 特异度，各一行）→ M3 → M4 → M5 / M6（构图）→ minor。修复时要保护已经成立的显影三段停顿、剪副券落袋和红蜡笔审核语言。
