## 通过的项目（有证据）

- **展开 / 返回（未滚动时）**：主体帧从 t=0 起穿着源帧的外衣（尺寸、灯箱光、下半段 ghost），一路放大到详情位置，下方区块依次显影，底层 `scale(.955)+brightness(.3)` 在裁切窗口外看得见（open-back f01–f06）；返回时帧一路缩回槽位，落点描边 1.4s（f16–f22）。暗帧 → 票面同样连续（open-back f27–f30、f38–f42）。
- **显影出票**：相纸从显影盘液面下分「露边 → 半张 → 整张」三段升起，两次停顿清楚，影像以斑块遮罩显出，镊子只在显影中出现；显影中没有可误按的按钮（print-tear f03–f16）。成局后先滚到顶再显影（confirm f07–f19）。
- **剪副券**：裁刀从左端开始，已剪段下沉、微转，与未剪段分得清；未过阈值回弹（print-tear f20–f28）。过阈值后先写入，副券卷曲落进底片袋，「存根 1」，红灯联系层滑入（f33–f50）。复制 → 「已复制」+ toast；已加微信 → 记录中 → 待赴约（禁用）（f51–f60）。
- **熔穿**：同一张帧 / 票从完整开始 → 起泡 → 洞推进、四层焦环 → 冷却 → 洞里淡入 `VOID · 已熔穿` + 说明；偏心，局名、时间首字和四角留下；没有白块（cancel f13–f37，withdraw-exit f24–f45，resched-decline f14–f37）。拖帧、释放、重播、重置都有效（scrub-replay f03–f27）。取消首开熔一次，再开是静态残片（history f21–f47）。
- **改期**：参加者侧旧票压暗、新票带「时间已改」章显影，剪新副券后出 toast「已接受改期 · 按新票根的时间见」，已加微信沿用 → 待赴约，返回落到「就快见面」（resched-accept f03–f39）。局主侧：同一时间和空日期时按钮禁用并有提示，合法后可点，「发出中…」→ 重印 → toast `已改时间 · 等 4 位成员答复` → 改期答复 0/4 → 列表进入「改期中」（host-resched）。
- **审核**：接触印样 + 放大镜，只有放大镜里一个实体按钮；发出邀请时红蜡笔圈选，谢绝时划叉；申请 2→1→0、已处理、预留 1→2、空 2→1、座位格、分区徽标、成员区「已预留 剩 06:00:00」同帧更新；返回后这局移到「招募中」（approve-reject f02–f23）。连点只进引擎一次（stress f08–f11）。
- **散场与出席**：确认层 → 处理中 → 出席区接管、进度条换成 0/4；圈出 / 框选「未出席 · 待核实」/ 虚线「待定」；更正会重新打开三段，留下轨迹；4/4 后进入历史「1/4 人到场」，口径正确（待定不计入）（end-attend）。
- **草稿**：删除时格子收起、相邻格补位，撤销条带 10s 引线，撤销后回到原槽；10s 自动提交；删到 0 时，撤销窗口内就显示空态；摘要里删除后可以撤销（drafts）。
- **失败 → 重试**：四处写入都是处理中 → 红灯失败条 → 重试成功；剪票失败时副券回弹（fail-retry）。
- **身份 / 分区 / 滚动**：两卷胶片横移；分区切换时暗房灯先灭再显影；纵向折叠后身份拨片和分区行常驻；横滚时扫光跟随，「n/N」计数同步（switch-scroll）。身份 5 连点后落在正确的卷（stress f06）。
- **面板**：索引、速度、减少动态、关键帧滑杆、释放、重播、重置、演示数据、下一次保存失败都能用（panel.png 与 probe 日志）。
- **语义**：没有信用分；八种「没去成」的标题和副文各不相同（coverage j-d-*）；候补名单显示为 `L** / 你`；局主微信只在剪票之后出现；取消后成员行写「取消前已预留 · 预留作废」，不显示倒计时。
- **差异**：横向底片条 + 灯箱 + 相纸显影盘 + 底片袋 + 红灯面板 + 红蜡笔，Space Mono + Long Cang，「显影 · 剪 · 熔穿」三个动作。与其余九套至少在构图、组件、材质、过渡、核心动作五个维度上不同。

## Blocker

### B1 从滚动过的详情 / 管理页返回时，源槽位是一块空白暗矩形，或者只有半张帧（M4，第 1 轮 B1 在滚动路径上复发）
- **现象**：`closeDetail` / `closeManage` 用 `paneGeom` 把裁切窗口缩回槽位，但内层的平移没有扣掉 `.pbody.scrollTop`。页面滚动过时，主体帧位于裁切窗口上方，窗口里看到的是滚动后的暗色区块。实测（1×，详情滚到底 `scrollTop=205`）：返回的 520ms 里，主体帧最后停在 y=63，而槽位在 y=358，两者错开约 295px，主体帧始终不在窗口内；窗口卸下后，源帧才一下子出现。剪副券后，页面在 1240ms 时会自动下滚到联系层，所以「剪票 → 联系 → 返回」这条主流程每次都会出现这个问题。
- **证据**：scrolled-return f06（整屏变黑）、f07–f10（灯箱槽位上是空黑矩形，持续约 4 帧）；同目录管理页 f19–f23（标题重影、帧被裁掉上半截，然后跳位）；cut-return f07–f13（0.5×：槽位里只有下半张「待联系 / 撕票后 8 小时内联系局主」，局名和时间缺失）；cut-return-1x f06–f08（1× 下同样出现）。
- **违反**：§0「同一物件在运动前后身份连续……不能中途换成另一个素材或空白矩形」；验收单「key motions … start → process → landing」「object continuity」。
- **修复**：返回开始时先把 `.pbody` 滚到顶（减少动态下直接设为 0；否则用 120–160ms 快速滚动，或直接把 `scrollTop` 设为 0 并同帧补偿内层平移），再测量和收缩；也可以在 `paneGeom` 的内层平移里加上 `-scrollTop`，让主体帧始终压在窗口里。修完后，用 scrolled-return 和 cut-return 两组流重新验证。

## Major

1. **历史列表里的作废残留和详情里的残片不是同一个物件**。在管理页 / 票面上熔穿后的结果是一个大洞，带焦环和 VOID（cancel f38–f40）。返回列表后，同一帧在「已取消 / 未成行」里只剩一圈很淡的棕色描边环，读起来像暗帧上的水印（cancel f42–f46，resched-decline f43–f44，coverage h-history-many 的「河边野餐」）。再打开又变回大洞（cancel f47）。飞回途中，帧面还带着奶白灯箱和大洞（f41），落地那一帧换成暗帧加细环，能看到素材被替换。**修复**：列表格的残留用同一个最终 mask（按格的尺寸缩放热源和半径），洞里透出暗色，焦环冻结；飞回时帧面按历史格的外衣（暗帧）过渡，让列表、飞行、详情三处的洞形一致。
2. **减少动态下撤销与反馈全部失效**。`after()` 在 rm 下 k=0，于是 10s 撤销计时、2600ms toast、1800ms「已复制」都在 0ms 时触发：删除草稿时没有撤销条、没有「已删除」提示，草稿直接被永久提交（reduced-motion f19–f21；probe：删除 400ms / 1.5s 后 `.undo` 都不存在，`state.undo=null`）；复制后按钮马上回到「复制」，toast 为空（probe）；「已改时间 · 等 N 位」「已接受改期」这两条 toast 也看不到。**修复**：撤销窗口、toast 停留、「已复制」这类产品计时不要走 `after()` 的速度缩放（单独写一个不缩放的计时器，或在 rm 下传入原始时长）；只有动效时长按 rm 缩短。
3. **两个首屏上，下一组的组头文字从底栏下面透出来，压在导航图标上**。`.nav` 的背景是 `linear-gradient(transparent, var(--dk) 34%)`，图标那一行仍然半透明，于是参加者首屏「还在等 3 · 等局主或其他成员」叠在「找局」放大镜和「设置」图标上，局主首屏「招募中 1 · 还没成局」同样如此。这是静止画面里的文字和图标重叠（coverage j-home、h-home 底部；switch-scroll f00、f20）。**修复**：底栏从上沿 8–10px 起就完全不透明（渐变只留在底栏上方 20px 的羽化带），或者给 `.roll` 加底部 mask，让内容在底栏上沿之前淡出。
4. **长标题下，管理页主体帧的状态行和帧号、下边缘重叠**。管理页帧面固定 190px，长地点折成两行，把「2 份申请待审 · 全员（含你）确认后成局出票」压到了角标「Nº 03 · 12.19」和下齿孔轨上（long f07、f09、f11–f12）。规格要求「只有地点可省略」，这里地点没有省略，反而挤坏了状态行。**修复**：主体帧里地点单行省略（`-webkit-line-clamp:1`），或者帧面高度改为 `min-height` 并让角标跟着内容走；改完用 b-long-h 重新验证管理、改时间、取消三个界面。

## Minor

1. 展开时的交叉淡化有文字叠字：源帧的状态行「已预留 剩 04:21:00」在淡出，正好叠在淡入的「Brooklyn · 威廉斯堡」上（open-back f01，放大可见）。地点行应等 ghost 淡出 120ms 后再进，或者错开 y 位置。
2. 返回时有约 150ms×k 的整屏近黑帧（区块先暗下，窗口还是全屏），而且收缩窗口里会带上页顶的返回栏「‹ 返回 我参加的 · 历史」一起飞（open-back f36，cut-return-1x f06，withdraw-exit f13，resched-decline f41）。返回栏应先淡出，背景应在暗下的同时恢复。
3. 改时间重印时，大号时间横向跳了两次：新时间先单独出现，删除线的旧时间插进来后，新时间右跳约 75px；1.8s 后旧时间消失，新时间又左跳回去（host-resched f08–f12、f19–f20）。旧时间应占固定宽度的槽位，或者用宽度过渡。
4. 删除草稿时，收起的格子里文字被挤压折行（「日期未定 · 地点未…定」「继续编辑 › 开局模块 · 不在本范围」变成多行窄列），标题直接消失（drafts f02–f03）。格子的内容区宽度应固定，用 `overflow:hidden` 裁切，或者先淡出内容再收宽。
5. toast 关闭时，文字先被清空，留下一个空的琥珀小方块在淡出（print-tear f63–f64，resched-accept f34）。清空文字要等淡出结束之后。
6. 失败条盖住了内容：取消确认层里「会受影响的人」的第三格「2 候补」被红灯失败条挡住（fail-retry f26、f28）；剪票失败条压在「按住裁刀…」提示行上（f02）。失败条应在层内占位，而不是浮在内容上。
7. 拖动裁刀后，「DEV · 显影盘」的「DE」两个字被选中，留下蓝色选区（fail-retry f11）。票面区域和显影盘都要加 `user-select:none`，pointerdown 时要 preventDefault。
8. 局主历史「已散场」里未记录的那局（看展搭子），状态和副文都写「2 人出席待记录」，同一句出现两次，也不是规格的历史口径 `n/N 人到场`（coverage h-history、h-history-many，probe）。历史侧应改为 `0/2 人到场`，副文写记录进度。
9. `p_history` 缺「不对劲？举报」局内记录层（说说发生了什么 ≥4 字 · 谁 chips · 截图 · 提交 → 已受理）和票根背面「点一下 · 看背面」，只有一行「补充一句」（coverage j-d-ended、j-d-absent）。补充可以保留，但要补上举报层入口与受理结果。
10. 未成行详情和空态的构图太空：撤回 / 未通过 / 退出候补 / 预留到期 / 放弃预留五页，「回到列表」以下 55% 以上是纯黑（coverage j-d-rejected、j-d-queueleft、j-d-withdrawn、j-d-expired、j-d-released）；七种空态是一截短片停在顶部，下面约 70% 留空（b-empty、b-empty-h、drafts f20）。可以把原定信息表、接触印样或一截未曝光片基放下来，补满构图。
11. 已预留详情的主按钮「阅读并确认」在首屏只露出一条边，被屏幕底边切掉（coverage j-d-invited、open-back f06–f15）。用户在列表里点了「阅读并确认」，进来后还要再下滑才能看到同一个按钮。按钮应吸底，或者把操作区移到状态块下方。
12. 散场详情「出席记录」的眉注仍写「局主记录的事实 · 不评分」，「不评分」是设计用语（第 1 轮 minor 8 的同类问题；coverage j-d-ended）。改为「局主记录 · 可补充」。
13. 局主取消时，确认层一收起，头部就换成「已取消」，进度行和候补分区也立刻消失，之后熔穿才开始（cancel f11 → f13）。灯箱侧洞里是一块均匀的灰褐圆盘，读起来像贴纸，不像透光的破洞（cancel f31–f37）。头部文字可以在熔穿 58%（熔穿阶段结束）时再落定；洞里加一点由中心向外的暖光渐变和片基纹理。

## 建议的修复顺序
B1（返回前把 pbody 归零或补偿 scrollTop）→ Major 1（列表残留用同一 mask）→ Major 2（产品计时不随 rm 归零）→ Major 3（底栏不透明区）→ Major 4（长地点单行）→ minor。修复时要保护已经成立的显影三段停顿、剪副券落袋、熔穿四层焦环与偏心残片，以及审核的接触印样 + 放大镜。
