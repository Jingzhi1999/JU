# C08 时间尺 · 评审 第 1 轮

评审方式：我自己私有构建（`JU_STANDALONE=.build/review-C08.html node src/build.js`），然后实际操作并截图。证据都在 `evidence/C08/review-1/<流程>/`（每个目录有 `f*.png`、`sheet.png`、`log.json`；局部放大图是从这些帧裁出来的）。`coverage/` 覆盖 50/50 个状态，0 错误。除 `panel-ops/` 外，每个流程的 `log.json` 错误都为空；`panel-ops/` 有一条运行时错误，见 M7。

**结论：不通过。** 1 个 blocker，10 个 major，15 个 minor。

## 做得好、修复时需要保护的部分
- 首屏有明确主角：lead 块、30px 倒计时、唯一的实体按钮。尺上的日期牌、铆钉铰链、刻度压印都很有材质感。两个首页的秩序都清楚（`coverage/j-home.png`、`coverage/h-home.png`）。
- 改期接受：块沿局部尺滑到 21:30，旧位置留下斜纹淡影，新位置分三段打印，出现存根槽、联系层和 toast（`resched-accept/f01–f22`）。
- 燃烧的阶段都在：完整票 → 中心起火 → 焦圈扩大并落灰 → 焦痕立起 → 滑进「历史尺」 → 结果构图（`exit-burn/f05–f15`；`cancel-half/f08–f27` 在 0.5× 下有 10 帧以上的破坏过程）。`cancelled` 只在第一次打开时烧一次，之后是静态的（`history/f15–f33`）。
- 审核：结果在原位替换按钮；计数、席位格、头部状态、组头「已处理 N」、徽标都随之变化；返回后落到新的分组，并有落点标记（`manage-review/`）。
- 散场 → 出席 → 更正：三段都不预选；章有三种形态；更正留下轨迹；计数正确（`end-attend/`）。
- 草稿删除 → 撤销条 → 原位展开（`drafts-undo/f01–f12`）；失败条与重试（`fail-retry/`）；减少动态直接显示结果（`rm/`）；长标题变体排得住（`long-detail/`、`coverage/b-long*.png`）。

## Blocker
**B1 撕票：副券纸从来没有分离。**
- 证据：`tear-drag/f05–f21`、`tear-release/f03–f22`、`coverage/j-d-contact.png`、`coverage/j-d-going.png`。
- 现象：票纸的底色、条纹和边框都画在不裁切的 `.c08-tk-face` 上；`c08-tk-keep` 和 `stub` 两层背景透明（computed style 已确认）。拖动时移动的只是「副券 · 撕下」几个字和箭头，到 f09 它们已经飘出票框外。撕完以后票仍然是 302px 全宽，右侧 84px 是一块空白纸，中间一条白色纤维线，外加一个打卡孔。所以「副券消失、面底锯齿」并没有出现，§6 的「分离部分有重量地移走、留下的部分对得上」也不成立。
- 修复：把票纸材质（底色、条纹、边框、阴影）分别放进 keep 层和 stub 层，各自配合 clip-path，去掉 face 层的底色。拖动时让整块副券纸（连同纸面、孔列、纤维边）移动。落定后不再渲染 stub，keep 层裁到撕口，并沿用列表里的 `--c08-jag` 锯齿边。存根槽里落下的应该是同一张副券的缩略。

## Major
**M1 撕后票面文字被撕口截断。**
- 证据：`coverage/j-d-contact.png`、`coverage/j-d-going.png` 局部；`resched-accept/f22`。
- 现象：`.torn .c08-tk-main{right:14px}` 让文字铺进了已被裁掉的区域。结果是「局主 蛋扌」「一起看《氵」「第」被切成半个字，打卡孔还压在「票根 · V2」上。
- 修复：撕后保持 main 的 `right:84px`，或者按 keep 宽度重新排版（标题限两行并省略，rows 换行）。打卡孔放到不和品牌行冲突的位置。

**M2 出票打印前，完整的票先闪现一次。**
- 证据：`detail-open-back/f03–f05`、`print-from-list/`、`read-confirm/f06–f08`。
- 现象：进入 `tear` 或成局时，票面先以印好的完整状态出现约 400ms（09:00、局主等字段都可见），然后被清成空白，再由印头重新印出来。同一物件出现了「完整 → 空白 → 完整」的身份跳变。另外，空白票纸一开始就整张原位铺好，没有出口，也没有「露出」的过程。
- 修复：需要打印时，第一帧就渲染为 `printing` 且 ink=0%。让票从 hero 块下沿的一道出纸缝分三段送出（clip 加 translateY），印头和墨迹揭示与送纸同步。

**M3 拒绝改期时，燃烧的物件和用户看到的不是同一个。**
- 证据：`resched-decline/f01`、`f07–f09`。
- 现象：答复面上是局部尺加旧块，再加一个红色虚线占位「新时间 21:30 · 等你答复」。确认退出后：成员、对照卡和局部尺瞬间消失；整个面板泛白；一张之前从未出现过的 21:30 票突然出现，然后被烧掉。
- 修复：答复面按 `p_answer_time` 的要求，一开始就在新时间位置显示打印好的新票（带「时间已改」章）。拒绝时让这张票原位燃烧，面板结构保持不变。

**M4 局主取消：局卡条先消失，再回来被烧。**
- 证据：`cancel-half/f05–f07`。
- 现象：抽屉关闭时，状态已经写成「已取消」，局卡条随即隐藏（约 600ms，0.5×）。随后 `forceTicket` 又把它渲染回来点火。物件「消失 → 重现」，结果先于动效出现。
- 修复：写入之后让局卡条持续渲染，直到燃烧结束（`forceTicket` 从确认那一刻就生效）。

**M5 取消后仍显示预留倒计时。**
- 证据：`cancel-half/f29`、`rm/f26`。
- 现象：成员行显示「Leon 取消前已预留 剩 05:02:00」。已取消的局不应再有预留计时。
- 修复：`cancelled` 时不渲染 `mb.leftText`。

**M6 局主管理面板打开时切到「参加」，面板不关。**
- 证据：`stress-role-over-pane/f03–f04`；probe 结果 `{role:'joined', manage:true}`。
- 现象：头部显示参加者身份，下面却仍是局主的申请人留言和邮箱验证。身份混乱，层也停在半开状态。
- 修复：`switchRole` 和 `switchSection` 先关闭 detail、manage、draft 面板（走 160ms 淡出），或者面板打开期间禁用头部切换。

**M7 「重播上一动效」会抛 TypeError。**
- 证据：`panel-ops/log.json` 记录了 `Cannot read properties of null (reading 'closest')`，位置在 `openDetail`。
- 现象：打开局卡后点重播，`ev.currentTarget` 已经是 null。M4 的打开动效无法重播，log 也不再为空。
- 修复：`motion('open-card')` 登记时把行 id 存下来，重播时按 `[data-rid]` 重新取矩形，并实现 `beforeReplay('open-card')` 先关闭面板。

**M8 历史「未成行」九种结局全部画成同一道焦痕。**
- 证据：`coverage/j-history.png`、`many-scroll/f09–f12`、`coverage/j-history-many.png`。
- 现象：rejected、withdrawn、queue_left、expired、released 从来没有票，也没有烧过，却和 cancelled、exited、declined 用同一种烧焦条。材质在说谎，九种不同的事实视觉上也无法区分；历史较多时，整页是一墙深色锯齿条。
- 修复：只有 cancelled、exited、declined 用焦痕。其余用尺上的空心或虚线刻痕槽，按结局区分形态（例如：未通过 = 断开的刻度，撤回 = 空槽，到期 = 停在 00:00 的刻度），文字留在浅底上。

**M9 尺上的时间倒退，主负责人复审的问题仍在。**
- 证据：`coverage/j-home.png`。
- 现象：「要你回应」组里依次是 六 12.19 → 五 12.18 → 日 12.20，块之间只有两道细斜线作为断尺。作为一把「时间尺」，第一屏就自相矛盾。
- 修复：在 act 组里，尺读的是截止时间而不是活动时间（刻度标「截止 HH:MM」）；或者每块各自成段，铰链和铆钉明显隔开，日期牌写成「另一段」。保持按截止排序。

**M10 管理面板丢失了「时间尺」语言。**
- 证据：`manage-review/f06`、`coverage/h-m-waitlist.png`、`coverage/h-m-replies.png`。
- 现象：面板里是同一种描边圆角抽屉的堆叠，申请、成员、候补、安排都一样，没有刻度和时间。主负责人复审「十套审核结构雷同」一条里，对 C08 的建议「申请挂在尺上」没有被采纳。面板的质量和特征都低于首页。
- 修复：给管理面板一条局部尺（和 hero 的 46px 尺段同一套语言）。申请按「申请于」时间挂在尺上；6 小时预留画成尺上的一段区间；改期答复区复用局部尺上的旧位和新位。

## Minor
1. **抽屉压暗实际变成了泛白。** 压暗是用 `.c08-pane.dimmed .c08-pbody{opacity:.42}` 实现的，浅色纸面上降低不透明度只会变淡。每次关抽屉后都有约 380ms 的淡化恢复帧（`read-confirm/f06`、`resched-decline/f08`、`manage-resched/f19`）。改为深色遮罩（`filter:brightness`），或在 pane 上叠一层 rgba 墨色。
2. **其他块被非等比压扁，文字模糊变形。** 打开和关闭面板时，其他块 `scaleX(.045)`，过渡中能看到压扁的文字（`manage-review/f02`、`f21`；`detail-open-back/f02`；`stress-role-over-pane/f08`）。先把文字淡出，再压成没有文字的色条标记。
3. **身份切换只是列表淡入淡出。** 方向卡写的是「两条尺并排切换」，现在是 200ms 的列表 cross-fade，过程很弱（`home-joined/f11–f14`）。
4. **三种作废用同一个燃烧效果。** 退出、拒绝改期、取消都是共享的正圆 fx-hole，读起来像打孔而不是炭化；纸烧尽后、焦痕出现前，有约 1 帧的纯白空框（`resched-decline/f13`、`cancel-half/f18–f19`）。建议改成沿尺方向（纵向）推进的不规则焦线，并让纸烧尽、焦痕立起、滑入历史尺三步交叠。
5. **复制 toast 盖住刚复制的内容。** toast「微信号已复制」压在微信号和复制按钮上，之后又压住存根槽（`tear-release/f23–f27`）。toast 应放到底栏上方的空白处。
6. **存根槽里落下的不是那张副券。** 落定物是一个很小的空白矩形，和被撕下的副券不是同一物件（`tear-release/f30`）。
7. **接受改期后，旧时间出现了三次。** 对照卡、淡影、票面「原定」都写了 20:30（`resched-accept/f22`），违反 G10「旧时间只出现一处」。删掉对照卡，或把淡影上的时间去掉。
8. **局主历史里计数口径不对。** 已散场的局显示「2 人出席待记录」，应为 `n/N 人到场`（`coverage/h-history.png`、`coverage/h-history-many.png`）。
9. **管理页写入失败的提示不在发生处。** 失败条出现在面板顶部，而不是出错的申请行，而且把内容整体下推（`fail-retry/f04–f06`）。
10. **连续删除草稿时，后面的点击被忽略。** 快速连删三条只生效第一条，其余点击没有任何反馈（`drafts-undo/f13–f17`）。
11. **状态重复写了两次。** 管理面板的头部右侧和 meta 行都写着「2 份申请待审」（`manage-review/f06`）。
12. **「更正」按钮位置跳动。** 出现轨迹后，「更正」从行右侧跳到左下（`end-attend/f28`）。
13. **撤回结果页过空，也没有物件动作。** 只有三行字加一个按钮，下方大片空白（`withdraw/f06–f10`）。
14. **倒放燃烧时画面与滑杆位置不一致。** 关键帧滑杆往回拖时，SVG mask 的洞和炭圈不同步（`scrub-burn3/f04–f06`）。
15. **深色已散场块上的灰字对比度过低。** 局主首页深色块里「已散场」的灰字几乎看不清（`coverage/h-home.png`）。

## 差异矩阵
- C08 与其他九套至少在构图（时间尺 + 块）、组件（块 / 抽屉 / 打孔）、材质（刻度压印 / 铰链铆钉）、过渡（块横向展开、尺不动）这四个维度上不同，满足「≥4 维」。
- 字体（Archivo Narrow + Noto Sans SC）与 C02 相同。
- 燃烧原语与 C03、C05、C06、C09 同源，因此「核心动作」这一维度的区分度偏弱（见 Minor 4）。
