# C08 时间尺 · 评审 第 2 轮

评审方式：我用私有构建 `JU_STANDALONE=.build/review-C08.html node src/build.js`，然后实际操作并截图。证据都在 `evidence/C08/review-2/<流程>/`，每个目录有 `f*.png`、`sheet.png` 和 `log.json`。文中的局部放大图是从这些帧裁出来的。另外用 playwright 直接读了逐帧的 DOM 和计算样式（probe），结果引在对应条目里。

- `coverage/` 覆盖 50/50 个状态。
- 33 个流程目录的 `log.json` 里 errors 全部为空。
- 0.5× 速度、暂停、关键帧滑杆、重播、重置、变体切换、「下一次保存失败」都实际用过（`panel-ops/`、`pause/`、`scrub-burn/`、`fail-retry/`）。

**结论：不通过。** 0 个 blocker，4 个 major，12 个 minor。第 1 轮的 B1、M1–M10 都已修复，并且我做了核验；minor 大部分也修了。这一轮的问题集中在三类：快速操作下的状态时序、两处切换的闪动，以及「散场」历史详情缺少票件。

## 做得好、修复时要保护的部分
- **首屏**：主角清楚，是当前线下的 lead 块。页面上只有一个最大字（30px 倒计时）和一个实体按钮。尺上的日期牌、铆钉、刻度压印都很有材质感。两个首页（`coverage/j-home.png`、`h-home.png`）的秩序一致。
- **三个核心动作的 起点 → 过程 → 落点 都在**：
  - 改期滑动：旧票块沿局部尺下行，溶进新票（`resched-accept/f06–f15`）。
  - 打卡撕票：`tear-drag/`。
  - 燃烧：一条不规则焦线从票的下沿向上推进，纸灰落下，焦痕立起，历史尺长出，焦痕滑进历史尺的槽（`exit-burn/f05–f33`）。
  - 局主取消在 0.5× 下有 28 帧破坏过程：完整局卡条 → 下沿起火 → 焦线上行 → 余烬与灰 → 16px 焦痕 → 历史尺长出 → 入槽 → 结果构图（`cancel-half/f10–f39`）。
- **管理**：审核结果原位替换按钮。待审、预留、空位、席位格、头部、组头「已处理 N」、徽标的计数都正确，返回后行落到「招募中」（`manage-review/`）。出席三段一开始都不预选，更正会留轨迹，`0/4 人到场` 的口径正确（`end-attend/f12–f38`）。
- **失败条都出现在发生处**：申请签内、撕票处（副券回弹）、取消抽屉内都有失败条，重试后都能成功（`fail-retry/`）。减少动态下直接显示结果（`rm/`）。长标题限两行加省略，时间不换行（`long/`）。
- **语义**：任何地方都没有信用分。八种「没去成」各有自己的状态词、副文和刻痕形态。参加者只看到局主微信，候补名单显示为 `L**`。

## Major

**M1 快速「返回 → 打开另一张块」时，新打开的面板会自己关掉。**
- 证据：`stress/f01–f04`。操作顺序：打开早午餐 → 400ms 后点返回 → 90ms 后点 Livehouse。f02 时 Livehouse 面板已经打开（「出票中」），f03 时整个面板消失，回到列表。probe 逐 150ms 采样，`view` 依次是 `detail, detail, list, list…`，即打开约 300ms 后被关掉。
- 原因：`closeDetail` 里的 `after(430)` 卸载定时器没有核对 detail 是否还是同一个，所以在新面板打开之后才触发。这正是验收单上「快速重复点击后不能有半开或卡住的层」那一条。
- 修复：给每次打开的面板加一个序号（或核对 `phase === 'out'` 且 id 一致），卸载时只清自己那一个面板；打开新面板时清掉尚未执行的关闭定时器；也可以在 `phase:'out'` 期间把新的点击排队。

**M2 改时间提交成功后，关闭中的抽屉闪出错误提示。**
- 证据：`resched-sheet/f09–f11`。提交前（f06–f08）显示的是正确的「原定 12.23 19:30 → 改为 12.24 20:30」。写入成功后，抽屉在关闭的约 380ms 里重新渲染成：
  - 「原定 ~~周四 12.24 · 20:30~~」；
  - 「改为 选好新的日期和时间」；
  - 红色「新时间和原时间一样，换一个日期或时间才能确认。」；
  - 「确认改时间」变为禁用。
- 原因：抽屉内容是从已经写入新时间的数据实时派生的。成功路径上出现了一条错误语句，这在局主最关键的流程里会误导用户。
- 修复：打开抽屉时冻结一份显示模型（旧时间、所选新时间），`phase:'out'` 期间沿用这份冻结值；或者在关闭时跳过「同一时间」校验。

**M3 「散场」历史详情没有票件：列表写着「历史票根 ›」，进去却没有票。**
- 证据：`coverage/j-d-ended.png`、`coverage/j-d-absent.png`、`history-expand/f28–f32`。列表入口文字见 `exit-burn/f34`（「已散场 记录为出席 · 历史票根 ›」）。
- 现象：详情只有深色 hero 块、一行「出席记录」（10px 圆章「到 / 未」）、局内记录和成员表。缺少以下内容：
  - 已撕票根的归档物件；
  - 盖在票上的出席章（出席 / 未出席·待核实（灰墨）/ 等章）；
  - `点一下 · 看背面`（背面 `JU. / 有 JU，就开局`）。
- 这些都是 state-inventory `p_history` 和 `ended` 行的必显项。结果是：被取消或退出的局在历史里有完整的「焦痕 + 历史尺」叙事，而真正去成了的局反而没有任何物件，这种结局的构图和质量明显低于首页。
- 修复：在 hero 下面的「历史尺」槽里放已撕的留存票（218px、右沿撕口、票版本号），按记录状态盖墨章（新鲜记录不重放），点一下翻到背面；局主微信只在散场 <24h 时显示。

**M4 分区切换时，新内容先闪出来，再淡出、再淡入。**
- 证据：`home-role/f09–f14`（发起 · 当前 → 草稿：f10 草稿内容已经是满不透明度，f11–f12 降到约 20%，f14 才回到正常）。
- probe 逐帧数据：点击当帧 `.c08-list` 里已经是「雨天读书局」，opacity 为 1.00 → 157ms 时降到 0.02 → 356ms 回到 1.00。旧分区的内容从来没有淡出。
- 两种身份、所有分区切换都会这样闪一次，属于 M2 动效族唯一的过程，也就是验收单上的「闪动」。
- 修复：先让旧列表淡出（保留一份旧分区快照 120–160ms），再切 `section` 并淡入；或者去掉淡出，让新内容从同一帧的 opacity 0 开始淡入。

## Minor
1. **身份切换中间有一整帧空白，身份胶囊也切得晚。** `home-role/f03`：正文区完全空（尺和块都不在），头部仍然选中「参加」，到 f04 才切到「发起」。probe 显示 167–268ms 期间列表 opacity 为 0。修复：推出和推入重叠约 200ms（两把尺同时在 DOM 里），胶囊在点击当帧就切换。
2. **返回列表时，所有背景块先变成空白纸块约 250ms。** 见 `contact-copy/f16`（1× 下返回 200ms 后，整屏都是没有字的纸块）、`open-back/f14–f17`、`exit-return-half/f08–f11`、`end-attend/f33`。契约写的是「不能中途换成空白矩形」。修复：文字淡入与纸面展开同时开始；或者只让源块附近的块走「裸纸」过程。
3. **退出 / 拒绝改期的结果构图是硬切换。** `exit-settle/f06 → f07`：存根槽、已关闭的联系层和成员表在一帧内全部消失，内容整体上跳。`resched-decline/f32 → f33` 里局部尺也是瞬间消失。修复：先把这些分区 240ms 收起，再让结果块淡入；或者把它们保留在结果下方。
4. **释放关键帧滑杆时，燃烧倒回起点重新烧。** `scrub-burn/f08`（70%）→ f09 纸重新长回几乎完整 → 再烧一遍。probe：滑杆在 60% 时 `--c08-bp` 为 0.60，释放后变成 0.02；而 `burnt` 定时器按剩余时间触发，在 bp≈0.80 时直接切到结果。修复：释放时设 `animation-delay: -frame·dur` 从当前位置续播，或者让定时器读取动画的 currentTime。
5. **取消后进度行和席位条一直留到燃烧结束。** `cancel-half/f07–f38`：头部已经写「已取消」，「已确认 2/6 · 预留 1 · 空 3」和席位格仍在；到 f39 才消失，hero 也到那时才变虚线。修复：写入当帧就让进度行淡出或变灰，与状态词同步。
6. **深色块上的状态色点看不见（黑点在黑底上）。** `coverage/h-home.png`（看展搭子「2 人出席待记录」）、`coverage/j-history.png`、`history-many-scroll/f06`。修复：深色块上改用浅色点或描边圈。
7. **散场后，管理面板的 hero 仍是白纸，而同一局在列表里是深墨块。** 对比 `coverage/h-m-attendance.png` 与 `coverage/h-home.png`，以及 `end-attend/f12` 与 `f38`。这是同一物件的材质不连续；而且「记为散场」本身没有归档的物件动作（M9）。修复：记为散场时 hero 用 400ms 转成墨色填充，这一步就是归档的落点。
8. **同一 tick 内连续点击「发出邀请」会叠出错误。** `stress/f20`：结果行「已发出邀请」上压着一条「这份申请已经处理过。」，文字一字一行竖排，重试 / 关闭按钮挤在里面。原因：`run()` 用 `this.state.busy` 做防重入，但 setState 还没生效。真实双击（`page.mouse.dblclick`）没有复现。修复：用实例上同步设置的 `_busy` 标志；`.c08-ierr` 放到结果行下方，而不是挤在同一 flex 行里。
9. **举报提交后的文字溢出抽屉右沿。** `report/f07`：「已受理 · 可在“设置 → 帮助与反馈”查询进度（不…」被截断。空表单（文本框、chips）仍然留在上方，结果读起来不像「已受理」。修复：允许这行换行；把表单替换成一张受理回执。
10. **候补详情缺少 `JU. / 候补回执`。** `coverage/j-d-waitlist.png`、`release/f13`：只有大号 №2 加名单，没有 `p_waitlist` 要求的回执纸件（`已加入候补 · NN 位` 等字段）。修复：在尺上挂一张回执签。
11. **连续删除草稿时，前面几份的撤销被静默丢弃。** `drafts-rapid/f03–f13`：三份连删后，撤销条只对应最后一份；撤销之后另外两份已经永久删除，界面上没有任何提示（共享 engine 只保存一份 undo）。修复：在本地排队，撤销条写成「已删除 3 份 · 撤销最近一份」；或者依次显示多条撤销。
12. **字体维度和 C02 不分家。** C08 用 Noto Sans SC + Archivo Narrow，正好是 C02 字族的子集（C02 另有 Unbounded）。差异矩阵仍然满足「≥4 维」（构图、组件、材质、过渡、核心动作都不同），但「字体」这一维没有区分度。建议把刻度数字换成例如 IBM Plex Mono 或 Bricolage Grotesque Condensed。

## 差异矩阵
C08 与其他九套至少在构图（竖尺 + 块 + 折尺）、组件（尺上挂签、6h 区间、刻痕）、材质（尺面压印、黄铜铆钉、票纸）、空间过渡（块拉成尺右侧面板，尺不动）、核心动作（沿尺滑动、沿尺上行的焦线、刻痕入槽）这五个维度上不同，满足「≥4 维」。字体维度和 C02 重叠，见 Minor 12。
