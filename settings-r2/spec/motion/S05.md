# S05 居中仪式 · 三个核心动作与关键视觉参数

命题：一条中轴。所有文字、控件、卡片、确认层都落在竖直中线上；节奏由留白与 32px 短线给出。首页的主导体量是称呼背后 360px 的环境光；每张二级卡片的头部重复同一团光（316px，几乎占满卡宽，是该页的主导体量），页面的主角（数字、结论、城市、状态、称呼）站在光里；卡片从被点的那一段的中心长出。三个核心动作全部用 `@keyframes` 写，接面板的 `.paused` / `.scrub`（`--frame`），并用 `this.motion(name, fn)` 登记，可重播、可暂停、可关键帧；减少动态（面板 / 系统 / 用户偏好任一）时时长压到 1ms，状态与结果不变。

## 1. sheet · 卡片从被点的段中心长出、收回原处（签名转场）

| 段 | 谁动 | 从哪里 → 经过什么 → 停在哪里 | 时长 / 曲线 |
|---|---|---|---|
| 触发 | 被点的段（称呼、收藏、城市、通知、外观、记录、举报、四个索引；卡片里的行与按钮；接缝的局卡 / 举报） | 按压：段的值 `scale(.97)`，胶囊 `scale(.958)` | 120ms ease |
| 发展 | 新卡片：外层 `.s05-shw`（scale .92→1、不透明度 0→1，45% 处已到 1）+ 裁切层 `.s05-sheet`（`clip-path: inset(段的盒子 round 20px)` → `inset(0 round 28px)`） | 起点矩形由控制器记录（`data-origin`），`componentDidUpdate` 在 enter 相位读一次卡片未变换的盒子，写 `--s5-ox/oy`（transform-origin = 段的中心）与 `--s5-ct/cr/cb/cl`（裁切起点）。其下：纸色幕 0→1（约等于其余变 0.6）；下一层卡片后退 `translateY(-10px) scale(.965)`、字降到 40% | 裁切 260ms、缩放 240ms，`cubic-bezier(.2,.8,.2,1)`；幕 240ms ease |
| 落定 | 卡片全尺寸居中：上 54px、下 30px（键盘时下沿 = 键盘上沿 + 30px），宽 `min(342px, 100% − 48px)`；长文页 `min(374px, 100% − 24px)` | 投影用 `filter: drop-shadow`，跟着裁切走（只有卡片 / 确认层有投影） | — |
| 文字何时可读 | 内容一开始就在终点排版，不缩放文字，只做整体 .92→1；约 110ms 起可读 | | |
| 打断 | 可以：新导航前控制器先结算当前转场（`_navSettle`），卡片直接到位 | | |
| 返回 | 先让卡片里的字退到 0（110ms），再把空白卡沿反向裁回原来那一段（scale 1→.92，最后 60% 淡出）；下层卡片回到全尺寸、字回到 100%。回到首页 / 接缝根页时重新量一次原段位置（值可能已变） | | 240ms `cubic-bezier(.4,0,.6,.6)`；控制器 back 260 |

确认层（未保存、退出演示）、系统权限弹窗、「N 件事等你」卡片用同一个 `s05-grow`（240ms），transform-origin 取最后一次点击的控件中心。根导航切换（找局 / 我的局 / 设置）：离场页 200ms 淡出，进场页 300ms 淡入 + 上升 10px。
登记：`this.motion('sheet')`；重播时 `beforeReplay` 先把导航栈恢复到点击前，再从同一段重新长出。关键帧：`.scrub` 规则把滑块换成负的 animation-delay（裁切按 260ms、缩放 / 确认层按 240ms 取帧），0 → 100 从段的盒子走到整张卡；转场结束后直接拖，面板自动重播最近一次核心动作并停在该帧。一次性的进场（确认层、幕、toast）用 `fill-mode: backwards`，落定后不留「仍在进行」的动画，自动重播才能触发。

## 2. value · 值在原位交叉淡入

| 段 | 谁动 | 说明 | 时长 / 曲线 |
|---|---|---|---|
| 触发 | 保存资料成功；选城市；开关提醒类别；预览 / 取消外观；拿出收藏 | | |
| 发展 | 同一位置叠两层（CSS grid 同格）：旧值淡出、新值淡入；卡片头部值立即开始，资料卡与首页称呼延迟 150ms（等上层卡片收回后才换） | 首页称呼在资料卡收回到称呼时换；资料卡在编辑卡收回到「编辑资料」时换 | 180ms ease |
| 落定 | 新值留在原位；资料卡标题下一行「资料已保存」、称呼下「刚更新」（8 秒后撤去）；值下的 32px 短线 120ms 内变为 JU 蓝、600ms 内回到墨色 | | 600ms |
| 返回 | 无反向；保存 CTA 依次显示「保存中…」（≥ 320ms 可见）→「已保存」（140ms）→ 卡片收回（240ms） | 普通保存在处理结束后 380ms 落定 | — |

登记：`this.motion('value')`；重播 = 清掉该值的过渡状态后再跑一次同一组旧值 → 新值。

## 3. skin · 环境换光

| 段 | 谁动 | 说明 | 时长 / 曲线 |
|---|---|---|---|
| 触发 | 外观页点一种环境（预览）、应用、取消预览；重置 / 跳转换数据时也会发生 | | |
| 发展 | 全部光层是伪元素：`::before` = 现在的环境，`::after` = 离开的环境（`data-sf`）。整屏底色 `.s05-env` 只做不透明度；脚光 `.s05-pool` 与所有光晕 `.s05-glow`（首页 360px、卡片头部 316px）做「新光从模糊里升起、旧光沉入模糊」（不透明度 .25→1 + blur 12→0；旧层 1→0 + blur 0→12） | 预览即整屏本身：页头底、卡纸（纸色渐变 + 两侧边光 + 底部脚光）、幕的颜色都随 `data-skin` 换 | 650ms `cubic-bezier(.22,1,.36,1)`（R3） |
| 落定 | 只剩 `::before`；连续切换用两组同义动画名（奇偶）保证每次都重新开始 | | |
| 返回 | 取消预览 = 反向换回已应用的环境 | | 650ms |

登记：`this.motion('skin')`；重播先安静地恢复到预览之前（不播放），再重新预览同一环境。

## 关键视觉参数

- **字体**：Noto Sans SC 400 / 500 / 700；JU 字标 15px/700，字距 .16em。
- **字号阶**：光里的数字 96（单位 22）/ 城市 56 / 称呼 48（长称呼 40）/ 卡片主角 44（事件与记录标题 30，「A · B」式标题在光里拆成两行）/ 页头 30 → 18 / 规则章名 30、规则编号 30 / 段值 26 / 列表段标题 22 / 规则标题 20 / 引文 18 / 正文 15 / 说明 14 / 标签 13（字距 .2em，`text-indent` 补偿居中）。标题只在词间（「·」之后）换行，不在名字中间断开。全页最小 13px。
- **色板**：墨 `#14161F`、正文 `#252b3a`、次级 `#535b70`、标签 `#3d4458`、JU 蓝 `#4553BE`（只用于主确认 CTA 与「N 件事等你」描边胶囊及其蓝点）、焦点 `#4A5AD6`、错误 `#DA3A52`、成功 `#0E9B76`。
- **环境（三种光的形状）**：棉糖 = 粉 / 紫 / 青三团叠成的水面圆；光晕 = 暖白圆心外一圈橙（`#ff5a10`）到紫（`#d0bce1`）的环；落日 = 上蓝中橙下黄的天色圆盘。整屏底色：棉糖晨粉、光晕暖白、落日蓝天到桃色。卡纸不是白纸：每种环境一条纸色渐变（棉糖 粉白→淡紫→淡青；光晕 暖白→杏白；落日 淡蓝→暖白→桃色），卡片两侧边缘各有一团固定的环境边光（左 40%、右 64% 高度，不随内容滚动），卡底一汪脚光；长页滚到中段时页边仍带着环境色，头部的光收拢成页头右侧的小光章。
- **光源与表面**：唯一光源是称呼背后的环境光；页底一汪同色脚光。只有卡片与确认层有投影（`drop-shadow` 0 26px 28px 15% + 0 5px 9px 7%），1px 8% 墨边，28px 圆角；没有玻璃、颗粒、持续发光。其下内容经 42% 纸色幕降到约 0.6。
- **页头收拢**：控制器写 `--hc`（0→1，96px 滚动）。首页 / 根页：标题 `font-size: calc(30px − 12px·hc)`，上移 28px 并右移 19px，与左移 27px 的 JU 字标在中轴两侧并排；辅助信息 `opacity: 1 − 2.2·hc`；页头底色是环境顶色，`opacity: hc`。卡片：标题同样 30 → 18（超过 6 个字的标题 24 → 18），收进返回按钮所在的工具行中部，卡纸色底条随 hc 出现。
- **开关**：一枚从中轴分开的胶囊「开着 | 关了」，整枚是一个 `role=switch`；开 = 墨色实心，关 = 浅灰实心。
- **二级页的构图件**（同一命题的不同排法，避免每页读成同一列行）：列表条目 = 「段」（13px 日期标签 → 22px 标题 → 14px 一行，条目之间 32px 短线）；三联（三个事实被两条发丝线分开：提醒的三层、记录的三类）；城市两栏（被选中的城市背后亮起一团 92px 的光，换城市时光从旧格淡出、在新格升起，260ms）；引文（人写下的话 18px，上方一枚环境色渐变的大引号）；进度（横向中轴上的节点，当前节点是一枚亮的小光）；规则章节（26px 小光 + 30px 章名，编号 30px）。
- **接缝根页**（找局 / 我的局）：与首页同一个页框，页头下方一团 288px 的光，站着该页的数（「21 个局」「7 个进行中」），其下才是筛选与局卡 / 段。
- **动作条**：主确认 / 资料页的「编辑资料」/ 详情的收藏胶囊站在卡底脚光上，位于滚动区之外，滚动内容在它上方 24px 内淡出；键盘弹出时它贴在键盘上沿之上，卡片背后的根页被纸色完全遮住。

## 一个仍可能失败的设计判断，以及我怎么检查

**判断**：所有二级页都是同一种居中卡片，头部是一团与首页同尺度的光。这让每一页都由同一个命题生成、每一页都有主导体量，也让签名转场到处成立；风险有两个：（1）十几页都以同一团光开场，缩略图里可能彼此难以区分、显得单调；（2）长列表页（`s-fav-many` 13 个局、`s-rules` 18 条约定、`s-records`、通知的 6 个类别）滚过头部以后读成「一张白纸上的一列居中行」。
**检查**：（1）每次改动后在 390 宽、默认环境拼 12 页接触表（首页、资料、编辑、收藏、收藏详情、城市、通知、外观预览、记录、记录详情、举报详情、规则），逐页确认光里站的是不同的主角（称呼 / 大数字 / 城市 / 结论句 / 状态 / 预览），光下面的构图件也不同（段、三联、两栏、引文、进度、章节）；（2）在三种环境里把 `s-fav-many / s-rules / s-records / s-notify` 滚到中段截图，看卡纸是否仍带环境色、两侧边光是否可见、行节奏是否 ≥ 56px，长文是否是两端对齐的测量栏（16px / 1.85，最后一行居中）。已知限制：在 390 宽的手机上，16px 正文的栏宽最多约 20–21 个汉字，达不到 28–32 字；我选了保持 16px 字号与 1.85 行距，而不是缩小字号去换字数。
