### blocker

**B1 预留已到期仍能「确认入局」，并直接成局出票**（根因在共享层，C01 里能用真实点击复现）
- 现象：阅读层打开时预留到期（面板「+5 小时」或等到 19:21），页头变成「预留已到期」，但提示仍是「请读到末尾，再确认入局」、底部仍是禁用的「确认入局」、右上仍有「去不了了」，没有「回到列表」也没有到期结果块；读到末尾后「确认入局」重新可点，点了以后数据从 `expired`（已过截止 39 分钟）变为 `tear`，界面显示「已确认 · 已成局 · 全员到齐，票根已出」。构建 B 与 C 都复现。
- 复现：我参加的 → 截止块「阅读并确认」→ 面板「+5 小时」→ 滚到末尾 → 确认入局。
- 证据：`op10d/log.json`（`stage: expired, expiredBy 39min` → `stage: tear`）、`op10b/z-expire-read.jpg`、`op10c/f000–f011`、`op14-recheck/f005–f006`（构建 C）。
- 建议：`ju-ctl.js` 阅读层状态判定只看 `cdR.expired`——结算后该行 `stage === 'expired'` 时倒计时不再报 expired，应同时按 stage / deadline 判定（primary「回到列表」、secondary 为空、hint「预留已到期，位置已补给他人」）；引擎的确认动作必须拒绝 `expired`；C01 可额外在 `c.read.row.stage === 'expired'` 时不渲染确认键。

- 证据：`op2b/z-landing.jpg`、`op6/z-home-card.jpg`（f053–f065）；源码 `_due()` 的 `originKey = 'due-' + id`，`landCls` 只比对这个 key。

- 现象：① 行 → 票根滑入，点下 170ms 后暂停，画面已停在终点（导航没被冻结）；拖关键帧 0 / 50 / 100 并不对应滑入的起点到终点，而是触发控制器「返回再进入」的重播，退场按真实时间播放，释放后再进入（`op12/z-scrub-nav.jpg`）。② 燃烧 C 进行中暂停，1 秒后火线继续推进（`op12b/z-scrub-burn.jpg` f1→f2）。燃烧的关键帧本身正确（0 = 完整票 + 左缘起燃，35 ≈ 烧去三分之一，70 起只剩灰，100 = 空），结束后直接拖关键帧会自动重播燃烧 ✓。
