# C03「双窗」· 动效与视觉实现记录（阶段 2）

源：`my-r2/concepts/src/C03.dc.html`（前缀 `c03-`）。构图一句话：30px 页头之下叠两张纸——**我参加的 = 82% 白纸**（环境光透出），**我发起的 = 深墨纸 #1B1D27**（不透明）；展开的那张在上，另一张收成底槽里的「三行摘要」（窗头 + ≤3 行 + 它托着的根导航）。换角色 = 拖 / 点把手，两张纸交换位置；详情、票根、管理在展开窗**内**横向推入，此时收起窗只剩窗头（窥视），另一角色还开着的页面在收起窗第一行以「正在看 · 票根 …」出现。弹层覆盖两窗。

时长约定：CSS 时长一律 `calc(Nms * var(--k))`（面板 0.5× → `--k` 2）；JS 动画（窗口弹簧、窗内推入）读同一速度。系统或面板减少动态时 `.app.rm *` 把过渡 / 动画压到 1ms，JS 动画直接写终值（`isRM()`），控制器 `after()` 归零。原件仪式（打印 / 撕 / 联系 / 燃烧 / 08 印记 / stampFace）的时长、曲线、尺寸不改。证据都在 `my-r2/evidence/C03/stage2/`，正常速度、只暂停环境引擎。

## 三、窗口与带的边缘（阶段 2 修正 1）

规则：静止时任何窗口边缘、粘性边缘都不出现半透明的字或被切的半行。
- **窗头带**是纸的一部分，列表盒从带的下沿开始（内容从不在带下方经过）；越过 lift 后带下沿是硬边 + 发丝线；从详情 / 票根返回时恢复滚动并吸附到行边，落定时没有一行被切在带下。对比：`fix-ghost/b-return-band.png`（阶段 1 tear/s17 vs 阶段 2 tear/s16–s17）。
- **展开窗的下沿**（被收起窗盖住处）不再用渐隐：移动时内容被边缘硬切（像一张纸压住另一张），**静止时**，被边缘切到的最下一块文字整块隐藏（一条 `--c03-fit` 裁线移到它的上沿；若它上面是组名 / 区块名，组名一起藏，不留孤立标题）；列表真的移动时裁线立即放开（程序把列表恢复到同一位置不算移动），`scrollend` 一到就重算（不支持时 160ms 兜底），收起用 150ms；返回时在 `back()` 的第一帧就按落定状态算好（见 M3）。内容被仪式改变（联系层展开、副券收起、印记场景）时由 ResizeObserver + MutationObserver 重算。对比：`fix-ghost/a-hosted-front-edge.png`（阶段 1 home/h-home-cotton：「阳台烧烤 · 自带肉」灰色半字 vs 阶段 2 同一位置）。

## 六、一个仍可能失败的设计判断与我如何检查

**判断：静止时把窗口边缘切到的那块文字整块藏起来（`--c03-fit`），而不是渐隐。** 这条规则消除了阶段 1 的半字残影，代价是：① 静止画面里展开窗的下沿会留出一段空纸（最多约一行加一个组名的高度），可能被读成「下面没有了」；② 手指滑停（`scrollend`）后被切的那行用 150ms 收起，快速滑停的人可能看到最后一行「被收走」。
**我如何检查**：50 张覆盖截图与本阶段全部证据帧逐张看边缘——静止帧里没有一处半字或被切的行（`coverage/`、`six/`、`env-*`、`variant-*`、`widths/`）；`m3-scroll` / `m3-scroll-h` 录屏里滚动一开始裁线就放开，滚完回到与起始帧相同的落点；返回落点用探针逐帧读（从票根返回：`back()` 第一帧 scrollTop 275、裁线 345，到落定后 600ms 都不变）；仪式改变内容高度时（联系层展开、撕后舞台收高、燃烧收灰）重算是否跟上（`tear`、`m7-accept`、`burn-*` 落定帧）；出席纸这种并列网格行，裁线不会切到旁边的章位（裁线上移到没有任何块跨越为止）。仍需用户验收：空纸是否被误读为列表到底——它下面紧接着就是另一张纸的窗头，我的判断是「纸压纸」的读法成立，但这需要真人看。
