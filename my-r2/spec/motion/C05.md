# C05「大面」· 动效与视觉实现记录（阶段 2）

构图一句话：上半屏是一块**不透明的彩色面**（环境自己的颜色），面上只放「这一场」——左列大字时间（42px）与右上的局卡原件（JuCardV2 212×265）并置，局名在卡下；下半屏是一张**纸**，放其余的一切（列表、成员、记录），纸可以上拉盖住面，面收成一条 84–108px 的带。进入任何一场 = 纸上的那一行**上升进面**（标题从行里飞到面上），返回 = 面上的标题落回原行。面的颜色就是状态：环境色（进行中）→ 票底灰（票根 / 作废的票）→ 褪色（没有发生的局）。

时长一律 `calc(Nms * var(--k))`（`--k` 1 = 正常，2 = 0.5× 评审速度；减少动态时 `.app.rm *` 全部 1ms，`after()` 计时归零）。行为全部来自 `this.ctlVals()`，数据先写、动画后放。原件（局卡、票根打印 / 撕 / 联系、燃烧 B/C、08 散场场景、stampFace、V27 CTA / 危险键）的尺寸、时长、曲线不改。证据：`my-r2/evidence/C05/stage2/`（CDP 截屏流，正常速度，只暂停环境引擎；帧标签是从真实 pointerdown 起算的毫秒；按主负责人规则只在 1 分钟负载 < 8 时录制、经共享 chromium 锁串行，负载写在每个序列的 `log.json.load`；关键时序另有页内逐帧探针 `fixes/after/*-probe.txt`）。

## 关键视觉参数
- **字体角色与字阶**（Noto Sans SC；数字 Archivo）：页标题 30/500（V27 title20）→ 收拢 18；辅助行 14；角色切换 15/500（当前 600 + 下划线）；日期 15/600 Archivo；**面的主角数字 42/700 Archivo（时间）/ 60（管理已确认数）/ 56（分区数）**；状态 14/600；地点·局主 14；局名 22/600（≤2 行、≤300px、balance）；副行 14（≤2 行）；卡位局名 20/600；纸上行标题 14/500 + 第二行 13（时间·地点 | 状态）；分组 12 字距 .06em；区块标题 15/600；帮助 13；最小 12（widths 实测）。
- **行宽实测**（`measure.cjs`）：面左列 100 / 124 / 164px（360 / 390 / 430）；局名 300px；纸上行标题 312 / 342 / 382px（草稿行改为标题满宽、还差什么放第二行）；局卡 212×265、票根纸 258、拿起的局卡 296×370、08 场景卡 212。
- **色板与前景面积**：面 = 环境色（棉糖 #EC6F8D / #9784DB；光晕 = 222° 丁香紫→沙赭→橙 / 丁香→藕紫→赭；落日 = 180° 珊瑚→杏色地平线→玫瑰→藕紫 / 冷紫 + 顶部暖光）；票底灰 #CFD5E6；褪色面（每个环境自己的灰）棉糖 #CBBCC1 / #BEBACD，光晕 #D0C4B8 / #C3BBCB，落日 #D5C2BA / #BCC0D0；面上墨 #2A0F1D（参加者）/ #17123A（局主），次级墨 = 同色 .9（不用浅灰）；纸 #F6F4F1，纸上次级 #535b70 / #62667a（≥ 5:1）。**面积**：390×844 首页面占 62%（纸边 525px），430 宽 56%，360 宽 67%；深层页 58–67%；票根页 75%；局卡 212×265 ≈ 屏幕 17%。对比度（渲染像素实测，三环境 × 首页两角色 + 详情 + 褪色历史 + 草稿卡位 + 作废压痕，146 个文字元素）：最低 5.11:1（草稿面 · 三环境），首页 ≥ 5.16，详情 ≥ 5.48（`stage2/checks/contrast.json`）。
- **光源 / 表面**：面是不透明色面（tint .94 盖在环境引擎上，一处右上白色径向高光 = 光从卡的身后来）；局卡投长而软的影（0 42px 84px −28px）向左下；纸是平的，顶边一道向上的影，到带时多一条 14px 发丝影；票槽是面里压下去的井（内阴影 + 下沿白边），压痕是井里的浅浮雕字（文字下 1px 白）；褪色 = 同一色相去饱和，不加纹理。
- **页头收拢**：`_faceP` 只写 `--c05-p` 与 `hc1`，其余全是 `calc()`；纸的起点 `--c05-ptop` 由面内容实测（≥486），票根页由票的实测高度 + 24（撕前在副券下、撕后在断口下、烧后在槽下；ResizeObserver 跟着票的纸）。

## 一个仍可能失败的设计判断与检查
**判断：面占首屏的 ≈60%，只放一场。** 面越大，「这一场」越清楚，但纸上的其余只露出 2–3 行（390×844 纸边在 525px；`many` 变体「还有 9 场」只看得到两行半）。可能失败在：待处理多的人（`pending` / `many`）第一眼以为只有一件事，或者要回应的那件不是面上那一场。
**我如何检查**：① 面上的那一场永远是控制器的 lead（最该先处理的那件），角色切换上的数字徽标 + 纸上第一行的说明「还有 N 场 · 要你回应 · N」在首屏可见（`variants/v-pending-*`、`v-many-*`）；② 纸上拉只需要 96px 就收成带（`motion/m3-scroll-many`：上拉到底再回滚，收拢与恢复连续，`many` / `history` 实测到达 p=1）；③ 360 宽、115% 字号下纸边仍在 525–554px，列表行标题 ≥312px（`widths` 无溢出、minFont 12）。若用户验收仍觉得列表太藏，退路是待处理 ≥3 时把纸的起点抬到 420px（面只保留时间列 + 卡，不放 CTA 行）。
**第二个风险（历史 · 散场）**：08 场景的引擎（4 个原件脚本 + WebGL2）首次加载时，DOM 局卡在原位占位 0.5–2s 再交给场景，两者的倾角不同，交叉时可能读成「卡跳了一下」。检查：`rituals/stamp-08-replay` 与 `motion` 录屏逐帧看交叉（卡只淡、不移动），引擎失败时退回 DOM 卡 + 普通章（`stampFallback`）。
