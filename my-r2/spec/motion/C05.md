# C05「大面」· 动效与视觉实现记录（阶段 2）

构图一句话：上半屏就是**活的环境本身**（三套环境引擎直接露出，上面只有一层半透明色纱给角色一个色相；修复轮按共同规则第 10 条改，原先是盖住环境的不透明色面），面上只放「这一场」——左列大字时间（34px）与右上的局卡原件（JuCardV2 212×265）并置，局名在卡下；下半屏是一张**纸**，放其余的一切（列表、成员、记录），纸可以上拉盖住面，面收成一条 84–108px 的带。进入任何一场 = 纸上的那一行**上升进面**（标题从行里飞到面上），返回 = 面上的标题落回原行。面的颜色就是状态：环境色（进行中）→ 票底灰（票根 / 作废的票）→ 褪色（没有发生的局）。

时长一律 `calc(Nms * var(--k))`（`--k` 1 = 正常，2 = 0.5× 评审速度；减少动态时 `.app.rm *` 全部 1ms，`after()` 计时归零）。行为全部来自 `this.ctlVals()`，数据先写、动画后放。原件（局卡、票根打印 / 撕 / 联系、燃烧 B/C、08 散场场景、stampFace、V27 CTA / 危险键）的尺寸、时长、曲线不改。证据：`my-r2/evidence/C05/stage2/`，修复轮在 `stage2/fix/`（CDP 截屏流，正常速度，只暂停环境引擎；帧标签是从真实 pointerdown 起算的毫秒；按主负责人规则只在 1 分钟负载 < 8 时录制、经共享 chromium 锁串行，负载写在每个序列的 `log.json.load`；关键时序另有页内逐帧探针 `fixes/after/*-probe.txt`）。

**关键帧 / 重播（修复轮）**：M1 / M2 / M4 的每个元素（带子的 clip-path、标题、卡、面色、交叉的副本）都是同一条 WAAPI 时间线上的动画，`_syncScrub` 把面板的暂停 / 关键帧值写成每个动画的 currentTime（滑杆 0 / 35 / 70 / 100 = 起点 / 带子过半前 / 将满 / 终点，`fix/scrub`）；静止时拖滑杆 = 重播上一次转场：先瞬间回到它的起点（同一任务内，过渡关闭、入场动画直接结束，不绘制），再从头播，滑杆停在它上面。首页倒计时条不再用宽度过渡（每秒重启的过渡会让评审 mixin 以为「还在动」而不重播）。燃烧进行中拖滑杆 = 定位这一次燃烧（画布引擎计入「在动」，不会被当成静止去重播）；拖到终点按住不落定，松手才落定，写入照常（`fix/burn-scrub.txt`）。

- **色板与前景面积**：面 = 活的环境 + 一层色纱（参加者 30% 环境暖色、局主 36% 紫系：棉糖 #EC6F8D / #9784DB，光晕 #DFA066 / #A98ACB，落日 #F7895C / #7F95DE）；票根 / 作废 = 66% 票底灰 #CFD5E6；褪色 = 60% 环境灰（棉糖 #CBBCC1 / #BEBACD，光晕 #D0C4B8 / #C3BBCB，落日 #D5C2BA / #BCC0D0）；弹层遮罩 rgba(20,10,22,.24)；面上墨 #2A0F1D（参加者）/ #17123A（局主），压痕墨 #383e51；纸 #F6F4F1，纸上次级 #535b70 / #62667a（≥ 5:1）。**面积**：390×844 首页面占 62%（纸边 525px），430 宽 56%，360 宽 67%；深层页 58–67%；票根页 75%；局卡 212×265 ≈ 屏幕 17%；纸上拉到底时深层页留 96px 带（首页 104 / 管理 108）。**环境露出**（`my-r2/tools/env-probe.cjs` + `env-count.py`，[直接, 透出] %）：50 个索引状态 + 9 个真实操作状态（阅读层三态、各页上拉到底）全部 ≥ 11.0%，最低 = 阅读层读到底 [10.0, 1.0]、票根上拉到底 [0, 11.0]（`stage2/fix/env/count.json`、`fix/env-steps/count.json`）。**对比度**（渲染像素实测，环境暂停，三环境 × 9 页 = 213 个面上文字）：最低 5.31:1（光晕 · 局主草稿副行 14px），首页 ≥ 5.34，压痕 ≥ 5.37（`stage2/fix/contrast/contrast.json`；落日草稿角色切换的一次误测（=1，切换中取色）重测 6.47 / 7.45，见 `contrast-recheck-sunset.json`）。
- **光源 / 表面**：面是活的环境（光与动态都来自环境引擎：棉糖水面、光晕光带、落日；不再有静态仿制的渐变与高光），色纱只给色相；局卡投长而软的影（0 42px 84px −28px）向左下；纸是平的，顶边一道向上的影，到带时多一条 14px 发丝影；票槽是面里压下去的井（内阴影 + 下沿白边），压痕是井里的浅浮雕字（文字下 1px 白）；褪色 = 同一色相去饱和，不加纹理。
- **页头收拢**：`_faceP` 只写 `--c05-p` 与 `hc1`，其余全是 `calc()`；纸的起点 `--c05-ptop` 由面内容实测（≥486），票根页由票的实测高度 + 24（撕前在副券下、撕后在断口下、烧后在槽下；ResizeObserver 跟着票的纸）。

## 一个仍可能失败的设计判断与检查
**判断：面占首屏的 ≈60%，只放一场。** 面越大，「这一场」越清楚，但纸上的其余只露出 2–3 行（390×844 纸边在 525px；`many` 变体「还有 9 场」只看得到两行半）。可能失败在：待处理多的人（`pending` / `many`）第一眼以为只有一件事，或者要回应的那件不是面上那一场。
**我如何检查**：① 面上的那一场永远是控制器的 lead（最该先处理的那件），角色切换上的数字徽标 + 纸上第一行的说明「还有 N 场 · 要你回应 · N」在首屏可见（`variants/v-pending-*`、`v-many-*`）；② 纸上拉只需要 96px 就收成带（`motion/m3-scroll-many`：上拉到底再回滚，收拢与恢复连续，`many` / `history` 实测到达 p=1）；③ 360 宽、115% 字号下纸边仍在 525–554px，列表行标题 ≥312px（`widths` 无溢出、minFont 12）。若用户验收仍觉得列表太藏，退路是待处理 ≥3 时把纸的起点抬到 420px（面只保留时间列 + 卡，不放 CTA 行）。
**第二个风险（历史 · 散场）**：08 场景的引擎（4 个原件脚本 + WebGL2）首次加载时，DOM 局卡在原位占位 0.5–2s 再交给场景，两者的倾角不同，交叉时可能读成「卡跳了一下」。检查：`rituals/stamp-08-replay` 与 `motion` 录屏逐帧看交叉（卡只淡、不移动），引擎失败时退回 DOM 卡 + 普通章（`stampFallback`）。
