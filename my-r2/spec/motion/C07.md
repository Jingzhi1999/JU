# C07「下盘」· 动效与视觉实现记录（阶段 2）

构图一句话：底部一块深墨「盘」（#14161F，一整张刚性的全高纸板，停靠时只露出顶部 `--th`）放**这一刻该做的那一件**；列表在盘上方的环境色光里流动。进入详情 / 票根 / 历史 / 阅读层时盘整张升满屏，返回时整张落回；进入「管理这局」时盘不升，**盘就是动作区**，上方列表换成名单。停靠高度随内容（`--thc` = 盘内当前块的实测高度 + 56px 导航，最小 160），盘内永远没有空档。

时长一律 `calc(Nms * var(--k))`（`--k` 1 = 正常，2 = 0.5× 评审速度，减少动态时 `.app.rm *` 全部 1ms）；JS 计时走控制器 `after / afterKey / holdKey`。原件仪式（打印 / 撕 / 联系 / 燃烧 / 盖章 / stampFace）的时长、曲线、尺寸不改。证据：`my-r2/evidence/C07/stage2/motion-*`（CDP 截屏流，正常速度；环境引擎渲染后暂停；只在 1 分钟负载 < 8 时录，开始 / 结束负载写在各目录的 `load.txt`）。

## 命题与数据的差异（记录，不改数据）
命题把「成局出票」写成之后就「就快见面」。数据（`ju-data.js` derive.joined）里出票后的 `tear` 仍属 **act（要你回应 · 待撕票）**，`contact` 也是 act（待联系）；只有撕票并自报加微信之后的 `going` 才进入 **soon（就快见面）**。C07 按数据画：成局出票 → 盘内的「先处理这一件」变成该局的「待撕票」，就快见面只在撕票 + 已加微信之后出现。

## 关键视觉参数
- **字体角色与字阶**（Noto Sans SC，数字 Archivo）：首页标题 30/600 → 收拢 18；升起页标题 30 → 18；盘内 lead 标题 24/600（两行省略 + balance）、表单 / 纸条标题 22/600；列表行标题 15/500；辅助 13–14；盘标签 13；倒计时 Archivo 16/500 等宽数字；CTA 15/500（V27 原件 280×48）；票面 / 局卡沿用票根原件字阶（标题 20/600、时间 Archivo 28/700、品牌 Space Mono 13）；章面标记 Space Mono 12；最小字号 12（widths 实测）。
- **行宽实测**（390 宽）：列表行标题 346px（360 → 316，430 → 386）；盘内标题 346px；CTA 280×48；纸条 346×96（姓名区 249 + 打孔副券 96，章面 64px 圈径）；局卡 / 票根纸 258px；草稿 / 历史局卡 258px 居中。
- **色板与前景面积**：墨 #14161F（盘 + 导航），盘内文字 rgba(244,245,250, 1 / .74 / .58)，盘内状态 绿 #4AD3A4 / 琥珀 #F2B14A / 红 #FF7A8E（盘上唯一的彩色是倒计时与回执）；列表 文字墨 #14161F、次级 #454b5e / #50566a（halo / sunset 各有更深的一套），状态 红 #B4223D、绿 #035A43、琥珀 #8A4B00、链接 #3B47A8；票纸 #EDEFF7。盘停靠高度实测（390×844，`stage2/measure.json`）：首页 lead 315–329px（37–39%，长标题 346–360 / 41–43%）、历史 / 草稿汇总 165（20%）、首次空态图例 277–309（33–37%）、管理动作块 238–296（28–35%）、出席台 284（34%）、表单 散场 309 / 取消 382 / 改时间 410 / 局卡 475（37 / 45 / 49 / 56%）。首页与管理的主 CTA 无论盘多高都落在 y=724（盘向上长，CTA 不动）。对比度（三环境，环境渲染后暂停的帧；首页两角色 + 出席深层页的名单区，WCAG 实测）：最低 cotton 4.87:1（行状态 / 徽标 13px）、halo 5.13:1、sunset 5.26:1（`stage2/env/contrast.txt`，共 9 组测量）。
- **局卡**：凡是「这局本身」出现的地方（完整局卡、局主取消、没有票的历史：审核未通过 / 撤回 / 预留到期 / 放弃预留 / 退出候补 / 没留住）都是 V27 局卡原件：`JuFilm.paintCard`（ju-paper-film.js，720×900，与盖章场景用的同一张卡）画在 V27 正面壳里（ju-card.css：圆角 13、1px 内描边、上下打孔），宽 258 与票根同宽；没有票的历史在卡上压一枚事实章（「这次没留住」「预留已到期」…）。字体由 C07 自己按卡面文字加载已声明的字族（上限 1.5s），不走 `JuFilm.loadFonts`（它等全部字族声明，内嵌字体里没有 Zhi Mang Xing，会等 24s 再失败）。草稿不是局卡：用票纸画，缺的字段留空位。
- **光源 / 表面**：环境光（skins 引擎）只在盘上方；盘是不透明墨面，只有顶边 1px 内高光 + 向上的软影；纸（票根、局卡、出席纸条）是盘里唯一的浅色物件，`mix-blend-mode:multiply` 的章只落在纸上或浅色列表上；第二层弹层是更浅一档的墨（#1D2130），不用白纸。
- **页头收拢**：控制器写 `--hc`，概念只用 `calc()` 插值（无 JS 改样式），收拢不改变滚动容器高度；列表底部留白 = 盘高 + 28px，最后一行总能滚到盘顶之上。

## 一个仍可能失败的设计判断与检查
**判断：盘高跟着内容走。** 盘内永远没有空档（阶段 1 的 50–60px 空带消失了），代价是盘和列表的分界线会随内容移动：回执、表单、局卡燃烧、角色切换都会让整张墨板滑动 320ms。可能失败在：连续操作（逐人记出席、连续审核、时钟连跳）时分界线来回动，读列表底部的人会觉得盘在「呼吸」，或者行被盖住又露出。
**我如何检查**：① 回执改为**替换标签行**（同一行高），连续审核 / 记出席 / 时钟回执不改盘高（`flow-enter-operate-return`、`motion-m9-attendance`、`clock/` 帧里分界线不动）；② 盘高只在块类型变化时变（lead ↔ 表单 ↔ 出席台 ↔ 结果），每次都用同一条 320ms 曲线，录屏逐帧看没有跳变、没有黑帧（M6 曾有一帧整屏变黑：根节点与表单块重名 `c07-form`，根节点吃到了表单的入场动画——已改名 `c07-formon`，`probe` 实测首帧亮度恢复）；③ `reveal` 改写成按盘顶判断，返回原行 / 跳到下一位都落在盘顶之上；④ 列表底部留白 = `--th` + 28px，`widths` 在 360/115% 下最后一行仍可滚出。若用户验收仍觉得「呼吸」太多，退路是把表单类（改时间 / 取消 / 散场）改成固定的「半盘」高度。
