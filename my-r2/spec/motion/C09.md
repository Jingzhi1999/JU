# C09「地点」· 动效与视觉实现记录（阶段 2）

构图一句话：「我的局」按**区**分节（曼哈顿 / 布鲁克林 / 皇后区 / 上州：24/600 中文区名 + N 场 + 右侧 12px 英文 + 2px 墨线），环境是底，唯一的白是顶部「先做这件」块（2px 墨色上沿 = 剩余时间）；进入一场时，**这一场所在区的节头就是深层页的区带**（V27 进度块的位置），票根从区带墨线下 24px 挂出（墨线 = 出纸口）；管理页各块、详情各节都用同一套节头字。

时长一律 `calc(Nms * var(--k))`（`--k` 1 = 正常，2 = 评审 0.5×）；减少动态：系统设置或面板开关 → `.app.rm` 下 1ms，`after()` 计时归零。行为全部来自 `this.ctlVals()`：**数据先写、动画后放**；所有位移 / 透明度都是 CSS transition（新目标一到就从当前值改道 = 可打断，返回键在任何阶段都可按）。原件（JuCardV2、票根打印 / 撕 / 联系层、燃烧 B / C、stampFace、08 出席场景）只经 `JURitual.*` 调用，不改尺寸与配色。证据目录 `my-r2/evidence/C09/stage2/`。

## 关键视觉参数
- **字体角色与字阶**（Noto Sans SC；数字与英文区名 Archivo）：页标题 30/500 → 收拢 18；辅助行 14（区索引）；区名 24/600 + 「N 场」13/500 + 英文 12/500 字距 .16em；行：局名 16/500 两行省略（`text-wrap:balance`，「·」不落行首）、第二行街区 13 墨色加粗在前 + 时间 / 局主 13 meta、第三行状态 13（字形 点 / 勾 / 圈 / 半圈 + 颜色 + 字重三重区分）；先做块：12/600 红标签 → 21/600 局名 → 13 → 倒计时 Archivo；「其余区」收尾节头 17/600 meta + 1px 线（同一语法降一级）。
- **行宽实测**：390 宽时内容列 346（左右 22）；先做块内文 310；局卡 212×265（详情左上，右侧事实列）；票根纸 258（区带下 24px）；确认层局卡 296。
- **色板与前景面积**：环境引擎为底（棉糖 / 光晕 / 落日），其上一层暖纱（`--c09-veil`，自上而下 .00 → .10 → .18；光晕 .04 → .34 → .47；落日 .02 → .27 → .40）；白色只给先做块与深层页的回执 / 局卡；墨色 #14161F 的 2px 线是唯一的强调结构；状态色 红 #B4233F / 绿 #086048 / 蓝 #3542A8 / 琥珀 #8F4A06（光晕、落日各深一档，光晕琥珀 #6a3504 按实测调）。
- **对比度（渲染像素实测，`checks/contrast`）**：取每个文字行盒在「原样」与「字形全透明」两张同帧截图里的差，字心取差最大的 20% 像素的中位色，背景取同一盒内的背景像素，报第 10 百分位（最差处）；三环境 × 首页（两角色）+ 票根页 + 详情页 + 审核页，≤18px 的自有文字全部 ≥ 4.5:1（见 checks/contrast/summary.txt）；V27 主 CTA 白字（实测 2.14:1）与局卡原件的 5px 小字属原件、未改，单列在报告里。
- **光源 / 表面**：环境光从上方来；先做块是唯一的纸面（白，长软影 0 20px 36px −26px）；局卡投 0 42px 84px −28px；收拢页头、吸顶节头、底部操作区是同一种磨砂（按不透明度保证下面的字不透出，截图里 backdrop 模糊不总是生效）。
- **页头收拢实现**：`_applyHc` 只写 `--hc`，其余全是 `calc()`；sticky 的 inset 从滚动容器的内容边算起，所以节头的 `top` = 收拢线 − 滚动容器 padding-top（阶段 2 修掉了「只有一场 / 历史」首节头压住内容的问题），`_stick` 用同一条线判定吸顶。

## 一个仍可能失败的设计判断与检查
**判断：进入一场时，列表在被点的区处「分开」，节头本身变成新页的区带。** 它让「我在哪个区、哪一场」在转场里一直可读，但风险是：分开的两组和到达的页面在同一区域叠印（阶段 1 / 2 初版都出现过「列表和新页都 30% 叠在一起」「先做块进入时区带没有来处」），或者为了不叠印而出现近空白帧。
**我如何检查**：只用正常速度 CDP 逐帧（每个实际绘制的帧）看三条路径——行进入（外百老汇小剧场）、先做块进入（详情）、先做块 CTA 进入（阅读，三层栈）以及各自的返回（`path-signature`、`path-lead`、`path-run3k`，负载 < 8 时录）。判据：每一帧至少有一个完整可读的结构（区带始终在，而且是实心的），同一区域同一时刻只有一层超过 30%。初版的问题逐条改到了时长里（离开 110 / 85ms 退净，到达 70 / 85 / 95ms 后才起），返回时首页被软滚 566px 的问题由 `data-measure="layout"` 修掉，并用 `steps-backscroll` 的读数确认 scrollTop 前后都是 0。仍可能失败的地方：负载高时 screencast 少帧，单帧看起来会更空——所以证据只取负载 < 8 的录制。
