## C01「左轴」· 动效与视觉实现记录（阶段 2）

构图一句话：左侧 52px 的日期脊（锚点 Archivo 22/600 数字 + 12px 小字）组织一切——首页按日、草稿按「改于 N 前」、历史按日倒序、深层页的锚点就是这件事的日期；右栏 302px（390 宽）放内容。所有深层页的脊与内容列和首页同一网格（脊 12–64，内容 76–378），页头标题与内容列左缘对齐。
时长都写成 `calc(Nms * var(--k))`：`--k` = 1（正常）/ 2（0.5× 评审速度）/ 0（减少动态）；JS 计时一律走控制器 `after()`（同样缩放、减少动态归零、可暂停）。原件仪式（打印 / 撕 / 联系 / 燃烧 / 盖章）的时长曲线不改。

## 关键视觉参数
- 字体角色与字阶：Noto Sans SC——页标题 30/500（收拢 18）、深层页事件名 19/500 两行省略 + balance、弹层标题 19/500、行标题 16/500 两行省略、正文 14/1.6、阅读约定 15/1.75、辅助 13、最小 12（脊小字、导航、图例）；Archivo——脊数字 22/600 等宽数字、截止时间 20/600、时间 13/500 等宽；票根 / 局卡 / 章为原件字体。115% 时全部 ×1.15，两行页头分开（身份一行、标题 + 分区一行），不溢出。
- 行宽实测：内容列 272 / 287 / 302 / 342px（360 / 375 / 390 / 430）；阅读约定 15px 在 390 下 302px 宽、平均 17 字 / 行（满行约 20 字）。
- 色板与前景面积：墨 #14161F、正文 #252b3a、次级 #535b70、蓝 #4553BE（链接 / 今天锚 / 焦点区）、红 #b02138（要回应 / 截止 / 危险）、绿 #086b51（就快见面 / 完成）、琥珀 #814a0c（改期 / 还差内容）；徽标底 #cf3048。首页实测面积：背景雾面约 71%、白色承托面约 17%、蓝（主 CTA）约 3.9%、墨字约 2%、红约 0.9%——颜色只给状态，大面积留给背景。
- 光源 / 表面：单一顶光——白承托面 rgba(255,255,255,.8) + 顶边内高光 + 柔投影；深层页只有截止 / 回执 / 局卡三类承托面，其余为无底文字 + 发丝线；halo / sunset 加 .3 / .26 雾层与更深的次级色保对比；底部导航与页脚用雾面渐隐托住 V27 CTA（不改 CTA 构造）。
- 局卡卡面只放主名（「·」前的部分，完整局名就在卡上方的页标题里），一行、词不拆；主名过长时按卡包的容量把字号收几个百分点（如「周五小酒馆试营业」×0.93），不在词中折行。
- 只有一条事实的历史页（未通过 / 退出候补 / 预留到期 / 放弃预留 / 撤回）在脊上接两段记录：「和局主 X 的其他局」与「前后 N 天内你的其他局」，每段是区块锚 + 几行只读记录（13px 次级色：日期 · 局名 · 状态，无状态色、无行形态、不可点；在列表里打开），不留空纸。
- 票根以 'fresh'（本会话未出过票）进入时与 'printing' 同样出票，不会留空纸位。
- 页头收拢：控制器写 `--hc`，概念只用 `calc()` 插值；收拢不改变滚动容器高度（不抖）；首页收拢标题水平中心用 `--tcx`（参·发钮右缘到分区标签左缘的空段中心，按宽度 / 缩放 / 分区计数测一次，字体载入后重测；只测已排版的页头——跳转后首帧曾量到 0 把标题压在参·发钮上，已改为未排版就稍后重试，七种进入路径实测标题都落在空段内），子页按 V27 水平居中。

## 一个仍可能失败的设计判断与检查
判断：页头收拢后把「我参加的 / 我发起的」换成脊头 44px 的「参 · 发」玻璃钮——为了让收拢后的工具行同时放下居中标题和分区标签，又满足「任一位置的身份切换」。可能失败在：第一次见到的人不一定把「参 · 发」读成身份切换。我做的检查：可达（Tab 可聚焦，aria-label「身份：我参加的，切换到我发起的」）；另一角色有待办时带红点；M1 帧序列确认切换后落到该角色记忆的分区与滚动；360 / 390 × 100% / 115% 与七种进入路径（冷启动、跳转、切身份、缩放）逐一量了标题、钮、分区标签三者的水平区间，互不相交。可发现性仍需用户验收。

**行宽实测**（文字列 = 屏宽 − 22 − 56 − 14 − 22）：360 → 246px · 375 → 261 · 390 → 276 · 430 → 316；先做这件卡文字列 = 屏宽 − 76（314 @390）；人名行 ≤3 个名字 + 计数单行，局名单行省略，时间永不折行，地点按实测宽度让位（`C2.fit`，分隔符实测 23px）。

**色板与前景面积**：墨 #1c1817 / #3a3431 / ink3 #58514e（Cotton）· #443a36（Halo）· #443a38（Sunset）；行动 #3441a3 / #1f2878；成局 #066a4f / #064532；警示 #b92e46 / #8c192e；纸 rgba(255,255,255,.96)；首字圆在白底上用 `--ta→--tb` 渐变（随环境）。白色表面面积（像素计数 r,g,b>238 且色度<14）：首页 Cotton 25.2%、Halo 19.7%、Sunset 19.5%；深层页 2–4%（人直接在色光上，局卡是米色原件）。对比度（文字色 vs 文字框内背景像素均值，live 环境 2× 截图，`evidence/C02/stage2/contrast/contrast.txt`）：首页最低 5.38 / 5.29 / 5.55，详情 5.49 / 5.63 / 5.81，管理 5.54 / 5.64 / 5.81（Cotton / Halo / Sunset），全部 ≥ 4.5；最低的是 13px 状态字与 12px 意图索引。

**光源 / 表面规则**：色光（共享 skins，Halo / Sunset 加一层提亮纱）是地面；**白 = 手里的东西**（先做这件卡、申请人 / 出席纸卡、弹层），其余都在色光上；首字圆：色光上是白圆、白卡上是染色圆；叠压的圆在后一枚上切出 2px 环（mask）；CTA 下是玻璃托；阴影色随环境（`--sh`）；首页与深层页底部的文字在 CTA / Tab 栏之前溶进色光（mask 118→58px），所以半透明的禁用 CTA 后面不会透字。

**页头收拢**：恒高覆盖式页头（绝对定位，滚动容器 padding-top = `--hdh`），标题高度由文字估算（`C2.th`，一行 31.5 / 两行 63），不读 DOM；`--hc` 写在滚动容器、表面与页头上（控制器 `onScroll`），C02 只在 ≥86px 时把标题切单行省略。

## 三、一个仍可能失败的设计判断与检查

**判断**：每一行都以人领起，`many`（13 局）滚到深处时可能读成「通讯录」——名字重复、每行都是「和 X、Y、Z」，靠第二行才认出是哪一局。

**检查与处理**：① 在 `j-many` 滚到 1300px、`j-history-many` 滚到 700px、`h-pending` 滚到 420px 截图逐张看（`motion/M3-*`）；② 局名从 14/400 升到 15/500（ink2），人名行仍 16/500 ink，三层仍是「人 > 局名 > 时间地点」，但每行第二行能一眼抓到；③ 同一组内相邻两行不再以同一个人领起（`_decoGroups`：与上一行首字相同就让下一个人领起，名字顺序同步旋转），首页局主侧「蒋 M 申请加入」下一行变成「M 蒋 待记录出席」；④ 脚本检查 8 个数据集 × 两角色 × 当前 / 历史 = 32 个列表状态：同组相邻两行以同一首字领起 0 处（default / pending / many / history / long 共 53 对相邻行）。仍未完全排除：同一人出现在多组时（如 `many` 里的「小面」）跨组仍会重复，这是数据本身的重叠，留给用户验收。

## 四、修正轮 A（2026-10-23）· 进入 / 返回不再有近空白帧，按下当帧有反馈

**问题**（主负责人复核阶段 2 帧）：path/ 进入 +216 / +271 / +293ms 与返回 33–34 帧只剩环境色 + 飞行首字 + 一行淡标题。**做法**：同一块面贯穿整个交接（见 M4）——按下时亮起的行面 / 局卡就是新页的纸，局名作为共享元素飞进新页页头（深层页页头因此改为这局的名字，状态着色写在副行），旧页内容在这块面上清掉、新页第一块在面上升起，首字从上面飞过；返回时纸收回成原行，落定那一帧交给行自己的落点光。深层页都铺同一张纸（`.c02-pgbg`，只有栈顶页显示，返回途中由下层页接上）。

## C04「叠层」· 动效与视觉实现记录（阶段 2）

构图一句话：首页是一叠**不透明的纸**。每张纸的颜色来自它那张局卡的 pack，在 OKLab 里降饱和到同一族；最上面一张（「这一场」lead）展开约 260px，局卡原件斜插在它背后、露出卡头；其余每张只露 70px 的纸带（局名 · 状态 / 日期 · 时间 · 地点）。点哪张，哪张纸就长成页面（详情 / 票件 / 管理 / 历史），但只长到页头之下：页头（返回、局名、meta、弱操作）和首页的页头一样，留在活的环境上（规则 10）。返回时纸沉回原槽。状态变了的纸（例如 Livehouse 接受改期后进「就快见面」）先停在旧槽，首页停稳后再滑到新槽。

时长一律写成 `calc(Nms * var(--k))`：`--k` 为 1 是正常速度，为 2 是评审用的 0.5×。减少动态时 `.app.rm *` 全部 1ms，`after()` 计时归零。行为全部来自 `this.ctlVals()`：先写数据，再放动画。动画进行中的输入由共享 nav 相位接住（enter / in / exit / idle，非 idle 时不受理第二次 go）。原件（局卡、票根打印 / 撕 / 联系 / 燃烧、出席章、V27 CTA / danger / back pill）只调用，不改它们的表面。

## 一个仍可能失败的设计判断，以及我怎么检查

**判断**：开页时，局名必须始终落在长大的纸上，返回时每一帧都必须有内容。为此做了三件事：

- 共享元素做成纸的子元素，坐标相对纸本身，所以它和纸在同一个合成层、同一套几何里，栅格再慢也会跟着纸一起慢，不会跑到纸外。
- 开页期间去掉滚动容器的 mask；那时滚动在顶部，mask 本来就看不出来，去掉后软件栅格不必每帧重建离屏表面。
- 返回不再飞局名：纸带着被裁剪的内容收回去，最后溶成下面那条真的纸带。

**仍可能失败**：在比本机（无 GPU，SwiftShader，负载 4–7）更慢的设备上，或者刚返回首页就立刻点下一张纸，新页面的首帧栅格可能被推迟。这时开页会整体晚一些出现，但不会压字。另外，阶段 2 中途确实出现过局名飞出纸面、压在别的纸上的帧，冻结取帧看不出这个问题。

**怎么检查**：每次改 M4 都录 1× 实时 CDP 录屏，并且用真实点击，不走索引跳转：

- `fix-r1/cast-1x`：纸带 / 首张 / 滚动后 / 阅读四种进入，以及对应的返回。
- `fix-r1/open-back-k1`：同一路径的逐帧取样。

需要 A/B 判断时，每个变体都在新页面里首开，避免缓存把差别抹掉（`stage2/fixes/m4-realtime-*.jpg`）。

## C05「大面」· 动效与视觉实现记录（阶段 2）

构图一句话：上半屏就是**活的环境本身**（三套环境引擎直接露出，上面只有一层半透明色纱给角色一个色相；修复轮按共同规则第 10 条改，原先是盖住环境的不透明色面），面上只放「这一场」——左列大字时间（34px）与右上的局卡原件（JuCardV2 212×265）并置，局名在卡下；下半屏是一张**纸**，放其余的一切（列表、成员、记录），纸可以上拉盖住面，面收成一条 84–108px 的带。进入任何一场 = 纸上的那一行**上升进面**（标题从行里飞到面上），返回 = 面上的标题落回原行。面的颜色就是状态：环境色（进行中）→ 票底灰（票根 / 作废的票）→ 褪色（没有发生的局）。

## 一个仍可能失败的设计判断与检查
**判断：面占首屏的 ≈60%，只放一场。** 面越大，「这一场」越清楚，但纸上的其余只露出 2–3 行（390×844 纸边在 525px；`many` 变体「还有 9 场」只看得到两行半）。可能失败在：待处理多的人（`pending` / `many`）第一眼以为只有一件事，或者要回应的那件不是面上那一场。
**我如何检查**：① 面上的那一场永远是控制器的 lead（最该先处理的那件），角色切换上的数字徽标 + 纸上第一行的说明「还有 N 场 · 要你回应 · N」在首屏可见（`variants/v-pending-*`、`v-many-*`）；② 纸上拉只需要 96px 就收成带（`motion/m3-scroll-many`：上拉到底再回滚，收拢与恢复连续，`many` / `history` 实测到达 p=1）；③ 360 宽、115% 字号下纸边仍在 525–554px，列表行标题 ≥312px（`widths` 无溢出、minFont 12）。若用户验收仍觉得列表太藏，退路是待处理 ≥3 时把纸的起点抬到 420px（面只保留时间列 + 卡，不放 CTA 行）。
**第二个风险（历史 · 散场）**：08 场景的引擎（4 个原件脚本 + WebGL2）首次加载时，DOM 局卡在原位占位 0.5–2s 再交给场景，两者的倾角不同，交叉时可能读成「卡跳了一下」。检查：`rituals/stamp-08-replay` 与 `motion` 录屏逐帧看交叉（卡只淡、不移动），引擎失败时退回 DOM 卡 + 普通章（`stampFallback`）。

## C06「字排」· 动效与视觉实现记录（阶段 2 + 修复轮 r1）

源：`my-r2/concepts/src/C06.dc.html`（前缀 `c06-`）。构图一句话：**没有容器的纯文字版式**——纸 #FBFAF7 + 墨 + 三种状态色；环境色光只在顶部 300px 渐隐；列表是一栏局名（衬线）+ 时间（Archivo）+ 一行状态；详情 = 点局名后**原地展开成一段文字**（局名不动、其它项下移），票根 / 局卡以原尺寸作为这段文字里的插图出现；唯一的实物是 V27 主 CTA，压在一条环境色光带上。

时长约定：CSS 时长一律 `calc(Nms * var(--k,1))`（面板 0.5× → `--k` 2）；JS 动画（展开窗口、滚动补间、FLIP 重排、弹层副本下沉）读同一个 `kf()`。系统或面板减少动态时 `.app.rm *` 把过渡 / 动画压到 1ms，JS 动画直接写终值；原件仪式（打印 / 撕 / 联系 / 燃烧 / stamp / stampFace）的时长、曲线、尺寸不改。所有动作都是**先写数据、再播呈现**：控制器写入后同一帧里列表、计数、状态字已是新值，动画只负责从旧位置走到新位置。

## 二、阶段 1 主负责人五项修正（前后对照见 `evidence/C06/stage2/fixes/`）

1. **返回 + 换组 ≤ 700ms、列表不等**：返回一开始就合窗（`onNav('back')` 当帧开始 `_collapse`），换组行在原位淡出、其它行同时滑，换组行在新位置淡入；整段落定 ≤ 700ms。阶段 1：155 → 1412ms。实测（终版 1×）：Livehouse 换组行在新位置落定 ≈570ms，run3k ≈670ms；合窗本身 ≤300ms。
2. **展开时无幽灵 / 叠字**：其它行 110ms 内淡到 0；快照前完成未完的窗口动画；打印位置（嘴 + 纸的虚线轮廓）提前占好。
3. **「先做这件」倒计时行让位不留空条**：倒计时行与光带随窗口收（文字保持可读，最后三分之一才淡）；收起时光带不越出自己这一行，切口是 26px 软边；展开段落里的倒计时等行内那条让位后（延迟 170ms、淡入 200ms）才出现，合回去时它先在 100ms 内退场、行内那条再回来——同一条倒计时不会同时出现两次。
4. **已加微信**：按钮字读 `c.ticket.contact.ctaLabel`、禁用读 `ctaDisabled`（处理中…）。
5. **确认层**：`danger / keepPrimary / okTone` 按本构图的文字动作样式：keepPrimary → 「留下」主 CTA + 后果红字（竖排）；okTone ink → 墨色字；其余后果为危险字。

## 四、一个仍可能失败的设计判断与检查方法

**判断**：详情不换页，而是在列表里原地展开成一段文字（局名不动，后面的局被推到下面并减淡）。风险是读者把展开的段落和下面减淡的局读成同一页的一长串，失去「我现在在这一局里」的感觉，或者不确定返回会回到哪里。

**怎么检查的**：①正常速度录了详情 / 历史 / 管理三种打开与返回（`evidence/C06/stage2/motion/sheet-M4.jpg`），逐帧确认局名只做一次到阅读位的滚动、没有第二层文字；②返回落点：未换组回到打开前的滚动位置，换组时停在原段落并看得见它去了哪一组（`signature/sheet-b.jpg`、`fixes/sheet-F1-return-regroup.jpg`）；③展开时工具行出现返回胶囊 + 本局的弱动作（去不了了 / 撤回报名 / 查看局卡），减淡的后续各局从 CTA 光带之下开始；④键盘：Esc 关弹层、焦点回触发字（`keyboard/sheet.jpg`）。仍需用户验收：减淡的后续各局是否被读成「这一局之外」，而不是这一局的一部分。

## 五、修复轮 r1（独立复核快照 0f028c080d4b 之后；证据 `evidence/C06/fix-r1/`，全部真实点击，报告 `evidence/C06/fix-r1.md`）

- **暂停 / 关键帧（M4）**：本套的运动全是脚本动画（窗口、兄弟项、FLIP、落点标记）加一个**滚动时钟**——滚动补间不再按 `performance.now()` 走，而是读挂在滚动容器上的一段空 WAAPI 动画的 `currentTime`。因此「暂停」= 暂停根节点下所有本套的有限动画（原件引擎另算：燃烧走 `seek / pause`，打印与印记有自己的时间线）；「关键帧」= 每段动画按自己相对本次运动起点的偏移设 `currentTime = 进度 × 总长 − 偏移`，0 / 25 / 50 / 75 / 100 就是展开过程中的五个位置（滚动、窗口、内容淡入、上方各局淡出同步）；「释放」= 从当前位置继续播完。运动结束后再拖关键帧：`lastMotion` 登记的是原地重放（列表回到打开前的滚动位置、窗口从 0 打开），不重走导航。
- **取消（M3 / M8 局主侧）**：`onEffect('cancelled')` → 弹层下沉的同时把该局头部滚回视野（360ms）→ 局名的墨色「抽色」到 #4F5466（halo / sunset #3D4254）900ms，同时 18 粒余烬（9px 暖色光点）从局名基线升起 30–70px 后熄灭（1.0–1.7s，随机错开 0–480ms）→ 落定为「已取消 · 不能撤销，票根作废、联系关闭」头部。减少动态：直接落定，无余烬。
- **撕票落定（M5）**：拖过半松手（或 Enter / 按钮）的那一帧，旧的「撕开票根 / 接受新时间」CTA 立刻淡出下沉（150 / 200ms，光带同时退）；联系层不再在断开时就打开，而是等副券落完（原件 `onDone`）才显出，副券不会落在按钮或联系层上；把联系层带进视野的滚动等票台收起后再起（一次 420ms），不再有断开那一帧的整页上跳；票台上方文字若改行高，票台用 transform 补偿，不换布局。
- **其它**：先做这件「去不了了 → 确认退出」→ 该行原位先换成结果「位置已释放 · 不记主动失约 · 已移到历史」1.3s、光带与 CTA 收起，再自身高度收到 0 退场（m3）；键盘撕票后焦点落在「复制」，「更正」后焦点留在这个人的「出席」（m5）；改时间提交后，答复区「改为 …」与头部时间从左到右重印（弹层下沉后才印），toast 改在粘底动作之上、不压页头（m8）；草稿空态加一份「一份草稿会记下：局名 / 时间 / 地点 / 人数」的字排提纲（m11）；减少动态下撕票圆点静止可见（m12）。
- **命题修正（m4）**：命题「局名不动」保留，但写明例外——段落里的原件（票根 258×351、局卡 212×265）放不进粘底动作之上时，列表滚动刚好放下原件的距离（一次，与展开同起同落）。理由：票根的副券要能直接撕、局卡要整张可见；若局名死守原位，点到中下部的局时副券会落在粘底 CTA 和根导航下面，撕不到。

- **复验补充（同轮）**：① 上方各局「一次退场」只在局名最终落到页头之下（列表顶 < 72px）时才做；只需短距离带起时上方各局留在原处、按 .28 变暗，不再留出一段空白（管理页、低处点开都是这样）。② 6 小时倒计时细条改为 `transform: scaleX(var(--ratio))`、去掉每秒 900ms 的宽度过渡：每秒变化 1/21600，看不出差别；原来那段每秒重启的过渡让窗口里永远「有东西在动」，复核面板因此判断不了「运动已结束」，关键帧不能重播。③ 草稿删除：收起的那一行的节点会被下一份草稿复用（列表按序号复用节点），换内容的那一帧关掉它的过渡，下一份草稿不再「淡出再淡入」；未命名草稿统一叫「未命名的局」（与撤销提示一致）。④ 状态行自身不重复：只是把状态再说一遍的单句（已撤回 · 申请已撤回）省掉；候补回执不再重复状态行的「轮到你时才开始 6 小时预留」；回执的粗体字段若已在状态里（候补轮到 · 已预留），不再出第二次。⑤ 换组行滑动时带一道很浅的抬起阴影（14px / 26px，.38 → 0，与滑动同长），读作一张被拿起的纸条，而不是一块白底。⑥ 打开已撕票根时联系层的补滚也受「局名在页头下 12px」限制：放不下就留给读者自己滚，不再把局名推到页头下面。⑦ 叠在另一段之上的段落（票根叠在详情上）在 pointerdown 就开始退后（变暗、上移、缩小），不等 click，并且从第 40ms 处起播（新动画的第一帧本来画的是起始关键帧），按下后的第一帧就已看得出；按下没点成（移出松手、pointercancel、1.5s 无 click）原路退回；收回列表的折叠仍在 click 时起（它会移动列表）。
- **复核第 2 轮两条（fix-r2）**：n1 取消抽色只有一次、单向：取消那一刻起局名用 fill backwards 保持墨色，480ms 后从墨色抽到 --cx（900ms），不再先灰、回墨、再灰。n2 toast 的位置每帧按版面量：有弹层时放在弹层上沿之上（弹层外）；没有弹层时放在它会盖住的那一串动作 / 联系层之上，留 10px；距离大（弹层升起）时一步到位，小的移动滑过去；副券下落时先不出，落地后再出，并从那时起留 2.2s。

## 一个仍可能失败的设计判断与检查
**判断：盘高跟着内容走。** 盘内永远没有空档（阶段 1 的 50–60px 空带消失了），代价是盘和列表的分界线会随内容移动：回执、表单、局卡燃烧、角色切换都会让整张墨板滑动 320ms。可能失败在：连续操作（逐人记出席、连续审核、时钟连跳）时分界线来回动，读列表底部的人会觉得盘在「呼吸」，或者行被盖住又露出。
**我如何检查**：① 回执改为**替换标签行**（同一行高），连续审核 / 记出席 / 时钟回执不改盘高（`flow-enter-operate-return`、`motion-m9-attendance`、`clock/` 帧里分界线不动）；② 盘高只在块类型变化时变（lead ↔ 表单 ↔ 出席台 ↔ 结果），每次都用同一条 320ms 曲线，录屏逐帧看没有跳变、没有黑帧（M6 曾有一帧整屏变黑：根节点与表单块重名 `c07-form`，根节点吃到了表单的入场动画——已改名 `c07-formon`，`probe` 实测首帧亮度恢复）；③ `reveal` 改写成按盘顶判断，返回原行 / 跳到下一位都落在盘顶之上；④ 列表底部留白 = `--th` + 28px，`widths` 在 360/115% 下最后一行仍可滚出。若用户验收仍觉得「呼吸」太多，退路是把表单类（改时间 / 取消 / 散场）改成固定的「半盘」高度。

## 一个仍可能失败的设计判断与检查

**全空时让三条带以「零高」留在原位（只剩组头、计数 0），而不是给一块空态面板。** 我的理由是：C08 的意义就是「带高 = 数量」，零就该是最矮的带——结构在，用户知道局会出现在哪；空态文字直接站在环境上。可能失败的方式：三条只有组头的色带在空屏上像三个「坏掉的容器」或占位骨架，而不是「此处为零」；落日环境下最上面那条深色带还会把视线拉走。检查：同一状态在三环境与灰度下并排看（`stage2/variants/empty-*`、`stage2/env/`），确认组头文字与「0」在灰度下仍可读、三条带的明度顺序与有内容时一致；再看 M11 的真实路径（最后一件处理完返回）——面收进零高带的组头、计数从 1 滚到 0，零高带是被动作「做出来」的，而不是凭空出现。如果用户仍把它读成骨架屏，退路是只保留第一条带（要你回应 0）并把另外两条并成一行说明。

## 一个仍可能失败的设计判断与检查
**判断：进入一场时，列表在被点的区处「分开」，节头本身变成新页的区带。** 它让「我在哪个区、哪一场」在转场里一直可读，但风险是：分开的两组和到达的页面在同一区域叠印（阶段 1 / 2 初版都出现过「列表和新页都 30% 叠在一起」「先做块进入时区带没有来处」），或者为了不叠印而出现近空白帧。
**我如何检查**：只用正常速度 CDP 逐帧（每个实际绘制的帧）看三条路径——行进入（外百老汇小剧场）、先做块进入（详情）、先做块 CTA 进入（阅读，三层栈）以及各自的返回（`path-signature`、`path-lead`、`path-run3k`，负载 < 8 时录）。判据（修复轮 2 定稿）：每一帧至少有一个完整可读的结构（区带始终在，而且是实心的），任何一帧只有一层文字（离开 80ms 退到 0，到达 90ms 后才起）——修复轮 1 的交叉淡化（两层各约 .55）被复核第 2 轮判为字压字，按统一标准改成两拍。阶段 2 的问题逐条改到了时长里，返回时首页被软滚 566px 的问题由 `data-measure="layout"` 修掉，并用 `steps-backscroll` 的读数确认 scrollTop 前后都是 0。仍可能失败的地方：负载高时 screencast 少帧，单帧看起来会更空——所以证据只取负载 < 8 的录制。

## C10「中轴」· 动效与视觉实现记录（阶段 2）

构图一句话：一条居中的纵轴。首页是外层标题「我的局」、意图摘要行（彩点 + 计数）、角色胶囊、分区；其下按意图分组：轴刻度（1×22px）→ 字距标签 + 计数 → 28px 意图色短线 → 状态圆点的行。每组的「先做这件」像一张请柬：13px 日期 → 32px Archivo 时间 → 24px 标题 → 意图摘要 → 状态与倒计时细线 → 席位条 → CTA。深页是同一条轴：被点的那一行的标题就是页标题（铰链），事实（日期 / 时间 / 地点）、结果与回执、各节（同局 / 参加约定 / 候补顺序 / 申请 / 出席…）都居中站在轴上；票根原件 258 宽不缩放、居中、原始出票口。

时长一律 `calc(Nms * var(--k))`（`--k` 1 = 正常，2 = 0.5× 评审速度）；WAAPI 时长乘 `kf()`。减少动态：`.app.rm *` 全部 1ms，且不计算运动模式、不起任何 WAAPI——页面直接是终态。导航相位来自共享控制器（`motionSpec` fwd 400 / back 500 / swap 340 / role 300）；处理中 `processMs` 360。
曲线：进入 `cubic-bezier(.22,.8,.22,1)`（快起、慢落定）；返回 `cubic-bezier(.4,.05,.25,1)`（慢起、轻落）；内容就位 `cubic-bezier(.2,.8,.2,1)`。

**只动 transform 与 opacity。** 第一版铰链用动画 clip-path 切开新旧两页；1× 实录里打印引擎初始化或大列表重渲染占住主线程时，clip-path 冻结 300–500ms，而合成线程上的标题照常飞行——于是出现标题压字、两页正文叠在一起。现在所有页面运动都在合成线程上，主线程卡住时最坏是「慢」，不会「叠」。

- **字体角色与字阶**：Noto Sans SC 400 / 500 / 600；数字（时间、计数）Archivo 500 / 600，tabular；Space Mono 只在原件里。外层与页标题 30 → 18（500，行高 1.05，两行 balance，中文词不拆）；请柬时间 32 / 600；请柬标题 24 / 600（两行）；深页事实时间 32；行标题 17 / 500（两行省略）；meta 与状态 13；摘要 / 地点 14；组标签 12、字距 .16em；全页最小 12px。
- **行宽实测**：390 宽时轴列 326px（左右 32px）；请柬标题 24px 一行约 13 字，行标题 17px 约 19 字；360 → 296px，430 → 366px；长标题两行省略，字号不随宽度变。
- **色板与前景面积**（棉花 / 光晕 / 落日）：墨 #14161F；次要 #535b70 / #363b4b / #383d4d；要回应 #BE2F4B / #86112D / #8E1431；就快见面 #0A7559 / #034C3A / #044F3C；改期 #3F4DB8 / #212C82 / #24308A；预留琥珀 #B0620A / #673300 / #6C3500。前景只有字、2px 意图短线、5px 状态圆点、4px 席位条；首页没有卡片（卡只属于管理页的申请、原件票根 / 局卡 / 章）。

## 一个仍可能失败的设计判断与检查

**进入时，被点那一行以下的内容第一帧就消失，新页正文从标题底边下方升起。** 我的理由：铰链的意思是「这行字把你带进去」，行以下的旧内容与新正文占同一片空间，任何交叉淡化都会叠字；让它们一帧离场、新正文随标题底边升起，是不用裁切也能保证不叠的唯一做法。可能失败的地方：① 行以下的内容一帧消失可能读成闪烁；② 17px 行标题与 30px 页标题的换行位置不同（两行长标题），第一帧标题会「跳行」；③ 返回时行若换了组，`reveal()` 会滚动列表，落点不在用户离开时的位置。检查办法：1× 实录（`stage2/signature`、`stage2/families`）逐帧看进入第 1–3 帧有没有空白闪与跳行（含 b-long 两行标题）、返回落点是否在屏内且亮起；任何一帧出现两段字相交即判失败。
