# 「我的局」R2 · 十套艺术指导命题（主负责人 v1 · 2026-10-22）

> 先在真实 390×844 里用同一份数据（`JU.data('default')`：参加者 8 场当前 / 局主 5 场当前）画出十种构图，匿名、同环境（棉糖）、灰度各看一遍，再命名。草案与对比表：`my-r2/sketches/`（`gen.cjs` 生成、`shoot.cjs` 截图；`out/sheet-*-half.png` 为留档）。草案只判断**构图与空间关系**，不是视觉定稿；每套的表面、光线、字体细节在构建阶段按本文配方做出，并由主负责人用实际画面复核。
> 名字只描述构图，不是道具或主题；编号 C01–C10 与旧十套无关。

## 0. 共同规则（十套都适用；与 `contract.md` §0–§1 一起读）

1. **先构图后装饰**：每一页先用纯构图 + 字体关系成立（灰度下能看出主次、重心、留白形状），再加入表面与光。不用噪点、堆渐变、粗阴影、玻璃模糊、装饰缝线替代关系。
2. **中文字阶**：每套只定义 4–5 个文字角色（局名 / 时间 / 地点与人 / 状态 / 动作），标题 17–26px、正文 14–16px、说明与状态 13px、功能标签 ≥12px；行宽按真实中文测量（`long` 变体 ≈40 字局名必须两行省略而不是换到第三行；地点可省略，时间不换行）。英文与数字只在时间、区名、JU 字标处出现，不做大英文衬底。
3. **固定物件原样进入**：V27 局卡模板（4:5，容器相对缩放；只用 V27 出现过的尺寸档：小 196×245、中 212×265、大 296×370、阅读 328×460，不自创更小档）、票根（面 258px、副券 258×84、打印 / 撕 / 烧原时长）、出席印记（R9 原件）、主 CTA（280×48 原构造）、外层标题（30→18 连续收拢）。每套要回答「它们在我的空间里放在哪、旁边是什么、进入和返回怎么走」，不能把它们缩小去迁就版式，也不能把普通页面包成另一件道具。
4. **三环境**：棉糖 / 光晕 / 落日是底层色光；每套说明前景如何在三者上成立（面、边、透明度、明暗面积），构建时三张首屏都截。
5. **组织意图必须可辨**：参加者「需要我回应 / 即将赴约 / 仍在等待」、局主「待处理 / 改期中 / 招募中 / 已成局」——分组方式可以不同（按意图、按日期、按人、按地点），但三种意图在首屏能分辨，且有唯一的「先做这件」入口（主 CTA 只出现一次）。
6. **深层页由同一构图生成**：详情、管理、出席、历史、空态都按本套的空间逻辑组织；不允许退回「返回 + 标题 + 列表」默认面板（任务书 §11 淘汰项）。
7. **内容压力**：13 场当前 / 15 条历史 / 只有一场 / 完全空 / 长标题 / 中英混排，每套都要在自己的构图里成立；条目不必同样大。
8. **正文宽度（旧十套实测教训，`baseline-old10.md` §11）**：普通条目的局名可用宽度 **≥ 268px**（旧稿 144–278px 被道具先占是主要小气来源）；任何固定左列 / 物件位都要用内容证明自己（日期锚、街区、人）并写进命题；第二条起正文不得退到 13px 以下（旧稿 10–12.5px）。
9. **日常路径节奏（旧十套实测教训）**：点击后 ≤80ms 有可见反馈，进入详情 ≤420ms 停稳、角色切换 ≤300ms 且无近空白帧，返回途中不能只剩一行标题；次要动作（去不了了 / 退出候补）到确认层 ≤320ms。旧稿 1.3–2.5s 且穿空白的路径是淘汰项。

## 1. 十套命题

### C01 「左轴」· 左侧日期锚 + 右侧完整内容（时间组织的认真研究）

- **语义选择（任务书 §06）**：**日期 / 时间分组轴**，不是真实日程轴。左列只放稳定锚点：日号（22px Archivo 600）+ 星期与月份（12px）；锚点之间等距排列**不表示时长**，没有细刻度，没有按小时拉伸的块。活动没有结束时间，不编造时长。
- **邀请截止与活动时间分开**：顶部「截止」块用自己的锚点（截止时刻 `19:21` + `今天截止`，红），承载唯一的主 CTA；活动轴上该局仍按日期出现一次，状态写「已预留 · 截止见上」。局主侧顶部块锚点是「现在 · 待处理」。
- **构图**：左列 52px（锚点）+ 12px 沟 + 右列 302px（局名 16px/500、时间 · 地点 · 局主 13px、状态 13px + 行内动作文字）。同日多场共用一个锚点，纵向堆叠；日期间 1px 细线。页头 30px 标题 + 14px 辅助 + 角色切换（下划线文字）。
- **分量**：截止块最重（白面、CTA），轴上各行同重，状态颜色给出意图（红 = 要你回应、绿 = 就快见面、灰 = 还在等）。
- **中文节奏**：右列行宽 302px，局名一行约 18 字；两行省略。锚点与局名顶对齐。
- **物件**：局卡与票根只在详情出现，详情保留左轴（锚点变为该局的日期，右列展开成详情；票根 258px 居右列中）。管理页同样保留左列：锚点换成区块锚（申请 / 成员 / 候补 / 安排），右列为区块内容——左列是整套的「脊」。
- **颜色与表面**：环境色光直接做底，右列行无容器（细线分隔），截止块与弹层用 82% 白面 + 轻接触阴影；冷墨文字。三环境：底色换，白面不变。
- **详情 / 管理**：右列滑入（x 轴 24px + 淡入 320ms），左列锚点交叉淡出为新锚点（180ms）；返回原路，锚点回到原列表且原行高亮 1.1s。
- **代表路径**：轴上点「公园慢跑 3K」→ 右列滑入票根面（打印若首次）→ 撕副券 → 联系层 → 返回：锚点 20 仍在，行状态变「待联系」原位落定。
- **时间变化**：改期后该局移到新日期锚点下，旧位置留 1 行「改到 12.18 21:30 ›」淡出 600ms；标题、局卡身份不变。
- **会失败的信号**：左列变宽、出现竖排字或小字；锚点被当作时长尺读；截止块与轴混成一条轴。
- **最近邻**：C09 地点（同样「顶部先做一件 + 分节列表」）。本质区别：C01 的左列是贯穿所有页面的脊（锚点在详情与管理里延续），分组轴是时间；C09 没有左列，分节标题横贯整行，分组轴是地点。

### C02 「人先」· 人物簇领行，局名退居第二行

- **构图**：每行以**人**开始：左侧首字圆簇最多 2 个 32px（叠压 −10px）+ 计数，簇位总宽 56px，文字列 ≥ 268px；第一行 16px/500「和 老杨、Momo、Leon 等 4 人」，第二行 14px 局名，第三行 13px 时间 · 地点 · 状态。先做的一件是一张白卡：52px 首字圆（最多 3 个）、21px 局名、「和 阿檬、小面」、倒计时、CTA。
- **分量**：人 > 局名 > 时间地点；页头辅助句写「这周要见 9 个人」。局主侧的人 = 申请人 / 成员 / 待记录出席的人（「阿蒋、Momo 申请加入」）。
- **中文节奏**：名字行用顿号，≤3 个名字 + 计数，不换行；局名 14px 一行省略。
- **物件**：详情顶部的人物簇展开成成员名单（圆 → 行，FLIP 380ms），局卡在名单之下以 V27 中档尺寸出现；票根页的人 = 局主（联系层就是「这个人」的卡）。管理：申请审核每行是一个人的卡（头像首字 44px、称呼、验证徽章、留言引文、通过 / 谢绝）；出席记录逐人盖章。
- **颜色与表面**：白卡与白圆在环境色光上；圆的描边 2px 用底色，形成「人浮在色光上」；暖墨文字。三环境：圆描边随底色变。
- **详情 / 管理**：从行到详情，人物簇留在原 y 坐标放大（共享元素），下方内容淡入；返回时簇缩回行内。
- **代表路径**：局主首页点「2 份申请待审」卡 → 两个申请人的卡依次滑入（间隔 60ms）→ 通过第一位：该卡原位换成「已发出邀请 · 等对方确认」，头部「已确认 2/5」变「预留 +1」，席位段盖一格 → 返回首页：该行的人簇多一个首字圆。
- **会失败的信号**：首字圆变成装饰、名字超过三个仍硬塞、局名被压到看不见；首页变成通讯录。
- **最近邻**：C06 字排（都是无容器的行）。本质区别：C02 的行由人物簇领起且有白卡 / 白圆实体；C06 行只有文字、无任何圆或卡，领起元素是衬线局名。

### C03 「双窗」· 两个角色同屏，分隔条即角色切换

- **构图**：页头 30px 之下两张纸：上窗（当前角色，展开）从 y=132 到底；下窗（另一角色）固定 300px 高叠在底部，深墨（#1B1D27）白字；两窗各有拖拽把手。角色切换 = 拖动 / 点击把手让两窗交换高度（M1 变成空间动作，300ms，两窗同帧）。
- **分量**：展开窗的「先做这件」白卡（17px 局名 + 13px 元数据 + CTA）最重；收起窗只显示该角色前三行（14px 局名 + 12px 时间，右侧状态）。
- **中文节奏**：两窗各自 20px 内距；行 9px 上下；收起窗行间 1px 10% 白线。
- **物件**：详情在**展开窗内**打开（窗内左滑，另一窗保持收起作为上下文）；票根在窗内居中；管理同样在窗内；弹层覆盖两窗。
- **颜色与表面**：上窗 82% 白 + 环境色透出；下窗深墨不透明；把手 36×4。三环境：上窗透出的底色变化，下窗不变。
- **详情 / 管理**：窗内推入（x 轴）；返回回到窗内原滚动位置；切换角色时正在打开的详情随窗收起（收起窗显示「详情 · 周六早午餐 ›」一行，再展开时恢复）。
- **代表路径**：下窗（我发起的）把手上拉 → 两窗交换 → 点「审核申请」→ 窗内申请卡 → 通过 → 返回 → 把手下推回参加者。
- **会失败的信号**：收起窗沦为装饰条；两窗字号被压到 12px 以下；深窗上的状态色不可读。
- **最近邻**：C07 下盘（都有底部深色面）。本质区别：C03 的底部面是另一个角色的完整窗（可交换、可操作其内容），C07 的底部面是当前角色的动作盘（只放先做的一件）。

### C04 「叠层」· 恒定露出的叠纸，每张纸带局卡配色

- **构图**：每场局一张纸（圆角 18px 上沿），纸与纸叠压，只露出上一张的 70px（局名 17px/600 + 时间 · 地点 13px + 状态右上）；最上面一张（先做这件）完整展开含 CTA；分组之间留 14px 间隙并以 12px 组名分隔。纸的底色取该局局卡 pack 的纸色（降饱和 20%），文字取 pack 的墨色。
- **分量**：第一张最重；其余靠露出的 70px 带状排列形成节奏；颜色来自内容（局卡），不是装饰。
- **中文节奏**：露出带内局名一行省略；展开后两行。
- **物件**：局卡本体在展开纸的右上以 V27 小档出现（纸色 = 卡色，形成「卡在自己纸上」的关系）；详情 = 该纸抬起并展开为整页（其它纸压缩到底部 24px 的叠边作为返回入口）；票根页同理（纸色 = 票底色 #edeff7）。管理页：区块 = 纸（申请纸 / 成员纸 / 候补纸 / 安排纸），叠压露出 56px，点开哪张哪张展开。
- **颜色与表面**：纸不透明、接触阴影 `0 -10px 24px -14px`；环境色光只在页头与纸间隙可见。三环境：间隙色变。
- **详情 / 管理**：抬起（translateY −8px + 阴影加深 120ms）→ 展开到整页（320ms，其它纸同帧压缩）；返回：整页收回原叠位，其它纸恢复。
- **代表路径**：点「周四 Livehouse」纸 → 抬起展开 → 改期答复：接受 → 新票打印在纸上、旧票作废 → 返回：纸移到新日期位置，露出带状态「待赴约」（数据里 Livehouse 改期前已撕票、已加微信，接受后直接是待赴约——C04 / C06 阶段 1 核实）。
- **会失败的信号**：露出带内文字拥挤；纸色过饱和变成彩条；展开后其它纸消失（丢失上下文）。
- **最近邻**：C08 色带（都是堆叠的彩色面）。本质区别：C04 的面是**每场一张**、颜色来自局卡、彼此叠压；C08 的面是**每组一条**、颜色来自意图、彼此并列不叠压。

### C05 「大面」· 上半屏一场的整面，下半屏其余的纸

- **构图**：0–500px 为一块饱和色面（取当前环境的主色：棉糖粉 / 光晕橙 / 落日橙蓝），面内：页头、角色切换、`周六 12.19` 15px + `11:30` 34px Archivo、局名 26px/600（最多两行，宽 ≤300px）、地点 · 局主 · 状态 14px、CTA。486px 起一张纸（圆角 26px）承载「还有 7 场」列表（14px 局名 + 12px 时间，右侧状态），可上拉。
- **分量**：一场占 60%；其余压在纸上。页头在色面里。
- **中文节奏**：色面内深墨（#2A0F1D 粉面 / #17123A 紫面）文字；纸上普通墨。
- **物件**：局卡在色面右上以 V27 中档出现（与大字时间并置，是这块面的「实物」）；票根页 = 色面变为票底灰蓝（#edeff7 的近色）承载票根 258px；管理页 = 色面承载头部状态与进度，纸承载区块。
- **颜色与表面**：面不透明；纸 #F6F4F1 + 上沿阴影；CTA 在色面上。三环境：面色跟随环境主色，纸不变。
- **详情 / 管理**：点纸上一行 → 该行的内容**上升进入色面**（色面内容交叉淡出 → 新内容淡入，纸下沉 40px 再回弹 320ms）——「谁在上面谁就是主角」；返回：纸上行高亮。
- **代表路径**：局主首页（紫面：`2 份申请待审`）→ 审核：申请人卡在纸上逐张滑入 → 通过 → 色面头部「已确认 2/5」原位落定 → 返回。
- **会失败的信号**：面色压过文字；大字时间与局名争主角；纸上列表被压到 12px。
- **最近邻**：C07 下盘（都是「一场 + 其余」的上下分屏）。本质区别：C05 主角在**上**且是彩色面、其余在下方纸上；C07 主角在**下**的深色盘里、其余在上方色光里流过。

### C06 「字排」· 无容器纯文字版式

- **构图**：纸底（#FBFAF7），环境色光只在顶部 300px 渐隐；单列 24px 边距、行宽 342px；局名 **Noto Serif SC 600** 21px（先做这件 26px）、`12.19 11:30` Archivo 500 14px + 星期 · 地点 14px、状态 13px；项之间 1px 12% 墨线；组名 12px 字距 .08em。没有卡、没有圆、没有阴影；唯一的实物是主 CTA。
- **分量**：靠字号与字重：衬线局名最重；时间次之；状态最轻但有色。
- **中文节奏**：衬线局名两行省略；行间 10/12px；留白形状来自段落。
- **物件**：局卡与票根在详情里以**原尺寸**出现在展开段落之中（像杂志内页的图），四周 24px 空白；管理页区块 = 段落标题（17px 衬线）+ 文字行；弹层 = 纸面上升的一段文字 + 两个文字动作（取消 / 主 CTA）。
- **颜色与表面**：纸 + 墨 + 状态三色；无面。三环境：顶部 300px 色光换色。
- **详情 / 管理**：**原地展开**：点局名，该项在列表中原位展开（其它项下移 320ms），局名不动；返回原地收起。没有飞行。
- **代表路径**：点「周四 Livehouse」→ 原地展开 → 新票（打印）出现在段落内 → 撕新副券 → 收起：状态行变「待赴约」，该行移入「就快见面」（同上，数据核实）。
- **会失败的信号**：变成普通白底列表（缺少字阶反差与留白形状）；衬线中文字重不够显得灰。
- **最近邻**：C10 中轴（都是文字主导）。本质区别：C06 左对齐、原地展开、衬线；C10 居中轴、轴向展开、无衬线。

### C07 「下盘」· 底部固定动作盘，列表在上方流过

- **构图**：页头 + 列表在环境色光上（14px 局名 + 13px 时间，右侧状态，细线分隔）；底部 318px 深墨盘（圆角 28px 上沿）固定，盘内：12px 标签「先处理这一件 · 已预留」、24px 局名、14px 元数据、倒计时、CTA；根导航在盘内底部。列表滚动时从盘下穿过。
- **分量**：盘最重（深色 + CTA + 大局名）；列表轻。
- **中文节奏**：盘内两行局名；列表一行省略。
- **物件**：票根页 = 盘上升为整页（深墨背景上票根 258px 居中，副券向右撕）；局卡在详情盘的上部；管理页 = 盘为动作区（通过 / 谢绝、记为散场、确认取消），列表区为名单 / 申请。
- **颜色与表面**：盘不透明深墨、CTA 光感在深色上最亮；列表区色光。三环境：列表区变，盘不变。
- **详情 / 管理**：盘上升（height 318 → 100%，320ms，列表淡出 160ms）；返回盘下降，列表原位。
- **代表路径**：盘内「阅读并确认」→ 盘上升为阅读层 → 滚到约定末尾 → 确认 → 成局出票打印在盘内 → 盘下降：列表「周六早午餐」行移到「就快见面」组，盘换成下一件。
- **会失败的信号**：盘吃掉一半屏幕却只放一行字；列表区被盘遮住最后一项；深盘上的小字 <13px。
- **最近邻**：C05 大面。区别见 C05。

### C08 「色带」· 意图分区即色域，高度随内容

- **构图**：页头（标题 30→18 收拢、角色与分区切换）直接在环境色光上（阶段 1 复核改：最初写的「页头在纸色上」把三套环境整个遮住，违反共有背景；带间 6px 缝也透出环境）；之下三条色带贯穿整宽：要你回应（环境主色，如棉糖粉 #E65C7E）、就快见面（JU 蓝 #4553BE）、还在等（浅灰紫 #E8E6F0 墨字）；每条带：13px 组名 + 口径（左右对齐），首条带含 22px 局名 + 14px 元数据 + 主 CTA（原构造，直接在带上——阶段 1 比较过骑缝 / 纸色段，二者都把带切断）；带内行 15px 局名 + 13px 时间，右侧状态，1px 30% 白线。带的高度 = 内容高度（空组不渲染）。局主侧：待你处理 / 改期中 / 招募中·已成局。
- **分量**：第一条带最重且最高；三条带的面积比例直接表达「要回应多 / 等待多」。
- **中文节奏**：带内白字 15/13；白线分隔；行内距 9px。
- **物件**：详情 = 该带展开为整页（带色成为详情的头部面，内容在带下的纸上）；票根在纸上；局卡在带色面上以中档出现。管理页 = 区块各一条带（申请带红、成员带蓝、安排带灰）。
- **颜色与表面**：带不透明，叠在环境色光上；纸 #F6F4F1 只用于需要阅读面的深层页（票根、详情正文）；无阴影。三环境：第一条带的色相随环境主色（粉 / 橙 / 橙蓝），第二条固定 JU 蓝。
- **详情 / 管理**：带展开（其它带被推出屏幕 320ms）；返回带收回。
- **代表路径**：局主「待你处理」带 → 展开 → 审核 → 通过两份 → 带内计数「待你处理 · 1」原位落定 → 处理完最后一份：红带收缩消失，下一条带上移（M11）。
- **会失败的信号**：带色压过白字对比；三条带高度相近失去表达；带里再放卡片。
- **最近邻**：C04 叠层。区别见 C04。

### C09 「地点」· 按区分节：哪里见

- **构图**：顶部「先做这件」块（12px 红标签「先回应这一件 · 今天 19:21 截止」+ 21px 局名 + 13px 元数据 + CTA，2px 墨线顶边）；之下按区分节：节头 24px/600 中文区名 + `N 场` + 右侧英文区名 12px 字距（唯一允许的英文）；节内行**满宽**（342px）：第一行 局名 16px/500，第二行 **街区**（14px/500 墨色，行首）· 星期 日期 时间 · 局主（13px），第三行状态。没有左列——地点的组织只靠节头与行首街区。
- **分量**：区名最重（是页面的大字），其次先做块，再是行。
- **中文节奏**：满宽行，局名两行省略；街区在第二行行首作为每行的「地址」。
- **物件**：详情从节内滑出，节头留在顶部作为「这局在哪个区」的面包屑；局卡在详情顶部中档；票根 258px。管理页：节 = 区块，节头 = 区块名（申请 / 成员 / 候补 / 安排）。
- **颜色与表面**：环境色光做底，节头与行无容器；先做块白面。三环境：底色变。
- **详情 / 管理**：节内 x 轴滑入 320ms，节头固定；返回滑出。
- **代表路径**：「曼哈顿」节点「外百老汇小剧场」→ 票根 → 查看联系层 → 返回：节头仍在，行高亮。
- **会失败的信号**：区名变成英文大字衬底；街区列把局名压到一行以下；只有一场时节头空洞。
- **最近邻**：C01 左轴。区别见 C01。

### C10 「中轴」· 居中轴版式

- **构图**：全部内容沿中轴居中：页头居中、角色切换居中、先做这件（`周六 12.19` 13px 字距 .08em + `11:30` 32px Archivo + 24px 局名 + 14px 地点 · 局主 + 状态 + CTA）、组名 12px + 28px 短横线、各项 17px 局名 + 13px 时间 · 地点 + 状态，左右 32px 边距。
- **分量**：先做这件占首屏上半；其余项等重，靠组名短线分节。
- **中文节奏**：居中两行局名；时间与地点一行；行间 10px。
- **物件**：局卡与票根居中轴出现（原尺寸）；详情沿轴向下展开（标题上移到轴顶，内容在轴上展开）；管理页区块居中标题 + 居中行（申请人卡居中 300px 宽）。
- **颜色与表面**：环境色光；无容器；CTA 居中。三环境：底色变。
- **详情 / 管理**：轴向展开（标题 translateY 到顶 320ms，内容淡入）；返回标题回落。
- **代表路径**：先做这件「阅读并确认」→ 约定沿轴展开 → 确认 → 出票打印居中 → 返回：该项移入「就快见面」。
- **会失败的信号**：居中列表读不出分组；长标题居中两行不齐；变成海报而不是产品。
- **最近邻**：C06 字排。区别见 C06。
