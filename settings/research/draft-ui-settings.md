## 三、跨案例可复用原则（设置 IA、当前值、分组、编辑／保存模型）

1. 总览页直接露出当前值：行尾灰色「Detail ›」（HIG）、行尾短词「High」「ON」（Android、Larussa）、或标签下一行摘要「Medium quality, auto-play on, PiP」（Android）；进入子页的入口文字必须与子页标题逐字一致。
2. 分组 = 容器 + 小标题 + 组脚：组头写分组名，组脚承担解释——Signal 用组脚写「这组字段谁能看见」，飞书把说明段落放在卡片外的灰字；只解释不跳转的行用 ⓘ，不用 chevron。
3. 即时生效与需保存分开：开关一律即时生效、不配保存钮（M3）；多选一次确认用复选框 + 保存（M3）；带校验的单字段用「取消 | 字段名 | 完成」模态或底部「关闭／保存」等宽双钮（Signal、Creliq）；邮箱变更走「新增 → 验证码 → 设为主 → 移除旧」而不是直接改字段（Notion）。
4. 通知分三层并各自写状态：应用内偏好（单选 + 开关）→ 系统权限状态卡（标题 + 状态说明 + 「去设置 ›」）→「收不到通知？」诊断入口（飞书）；依赖关系用父开关禁用子项并写明原因（Android Dependency）；开关带来的可见变化用一枚预览小卡示范（飞书横幅预览）。
5. 隐私可见性要给「我看到的 vs 对方看到的」双视图对照（Strava、Notion）：自己视角灰显 + 「仅自己可见」小标签，对方视角直接不渲染；默认值在首次保存后明文写出；单条记录可覆盖全局默认并标「已单独设置」。
6. 资料字段行式：小标签在上、值在下、右端辅助动作（二维码／复制／铅笔）（Telegram iOS、Signal）；头像编辑用头像角上的小徽标（Creliq）或头像下方「Edit Photo」胶囊（Signal）；资料页编辑入口放页头右上角胶囊（Telegram）。
7. 破坏性账号操作：红色文字钮独立于所有分组之外的末尾（Larussa），或确认弹层中最后一枚唯一填色的红钮，弹层给替代方案 + 加粗关键名词与期限的后果说明（Telegram）。
8. 控件选择规则：二值 → 开关；对立二选一 → 分段按钮；>2 互斥 → 单选列表；多选 → 复选框 + 保存；范围 → 滑杆；状态差异不能只靠颜色，开态加勾号或形状差异（HIG Toggles、M3 Switch、Android）。
